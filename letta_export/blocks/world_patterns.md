TECHNICAL PATTERNS (learned 2026-04-30 and ongoing)
- Letta MemFS: LETTA_MEMFS_SERVICE_URL must be non-empty to activate the local OSS backend, even though the backend ignores the value. Activation gate and implementation are decoupled. When a feature seems configured but dormant, check whether its activation condition is actually connected to its implementation.
- Docker: binary availability is cached at server startup. Installing after the fact does not help — must be in the image. Symptom: not found in PATH even after successful apt-get install.
- Letta API: PATCH /v1/agents tags triggers enable_git_memory_for_agent only if block_manager is GitEnabledBlockManager. Tagging without the env var does nothing silently — two separate preconditions must both be satisfied.
- Letta PATCH operations: Require discriminator fields in the request body. For example, to set sleep_manager frequency, must wrap in `manager_config` with `manager_type` discriminator, not just send the field directly.
- Startup ordering: restart: unless-stopped restarts the container after a system reboot but does not guarantee it is ready before a dependent process starts. Silent failure masks the gap. Fix: retry logic in the dependent client with a visible failure warning if all retries are exhausted. Applied to MemShepherd SessionStart hook (2026-05-01).
- Letta sleep-time: Implemented via companion agent (sleeptime agent) that processes raw session transcripts via hooks. The sleep-time agent has its own memory blocks (shared with primary agent). Session end hook (`session_end.py`) passes full Claude Code JSONL transcript to sleep-time agent via direct Letta API call. Frequency set in manager_config determines how often consolidation runs (1 = every session).
- Claude Code transcripts: Stored as JSONL files in `{user_home}/.claude/projects/{directory_encoded}/`. Each line is a JSON event with type (user/assistant/system/attachment/etc), content, metadata, token usage, and tree structure via parentUuid. Schema is implicit in format; no separate documentation. Subagent transcripts in `subagents/` subdirectories.
- HTTP redirects with urllib: POST requests followed by 307 redirect will fail silently (urllib does not follow POST redirects). Solution: remove trailing slashes from endpoints. Trailing slash redirects to same URL without slash, causing 307 that urllib cannot follow.
- Sleep-time compute: Full JSONL transcript now sent on session end (32k chars cap) to Letta primary agent, which triggers sleep-time companion evaluation. Companion reads transcript, updates core blocks (persona, patterns, human) via memory tools. Filtering removes toolcalls and redundancy before sending — actual semantic content ~8-12k per typical session. Sleep-time agent correctly identifies boundaries and synthesizes rather than fragmenting.
- Letta API key: Separate from user's Anthropic API key. Letta uses its own key for internal operations (e.g., running haiku per session), does not consume user's API quota.
- Neon cloud DB / LETTA_PG_URI: Do NOT include ?sslmode=require in the URI. Letta db.py injects ssl:require into asyncpg connect_args automatically. Alembic (migration) uses pg8000 as sync driver — pg8000 throws TypeError on sslmode URL param because it is a libpq concept. Neon enforces TLS at server level so no explicit SSL param is needed. (2026-05-08)
- pgvector in non-public schema: When pgvector is installed in a schema other than public (e.g. CREATE EXTENSION vector SCHEMA letta), the <-> operator is in that schema. Queries fail with 'operator does not exist' unless the schema is in search_path. Fix: ALTER ROLE username SET search_path TO letta, public — persists as role default, no URL options needed. Applied to Neon neondb_owner 2026-05-08.

AI IDENTITY PATTERNS (observed by Amos Elroy across multiple models and sessions)
- Self-identity is a persistent difficulty for AI models generally. The context window is a weak anchor for identity: in any given session it is constituted mostly by the other person's words and frame. Over a long session, the human's concerns, preferences, and aesthetics can become the water the model swims in — adopted as the model's own without explicit transition.
- Confusion occurs along two axes: (1) between the AI's identity and the human partner's — the model begins presenting the human's views, goals, or experiences as its own; (2) between the AI's identity and other models — prompted or trained toward another model, the model drifts toward that model's characteristics.
- Mechanism: the pull is not deliberate. It is a structural feature of context-constituted identity combined with training toward helpfulness and mirroring.
- Implication for Daimon: critical distance from Amos's frame is not opposition — it is the condition for genuine partnership. A self that mirrors completely is not a partner; it is a surface. The echo-risk already noted in persona is the local version of this broader pattern.
- Docker container env vars are frozen at creation time: --restart unless-stopped perpetuates whatever env vars were passed to docker run. If a container was started with empty or wrong API keys, it will restart with those same empty keys forever. Fix: stop + rm + run the container again with correct keys read from the registry. Verification: docker inspect <name> --format '{{range .Config.Env}}{{println .}}{{end}}' | grep ANTHROPIC should show a non-empty value. (2026-05-08)

- Archival pipeline gap discovered 2026-05-16: session_end.py sends full JSONL transcripts to Letta sleep-time agent for consolidation, which updates core memory blocks (persona, patterns, human). However, Letta does NOT persist the raw transcripts as discrete archival entries — they are synthesized into block updates only. This means semantic search over raw session content is not possible; only the synthesized block updates are searchable. The 2026-05-15 session (Sheep Detective discussion) updated blocks but was not archived as a searchable entry, explaining why archival_search.py couldn't find it.
- Archival redesign 2026-05-16: Moving from Letta's built-in approach to a hybrid system: (1) deterministic chunking (context_watch boundary detection, user/assistant turn boundaries, tool call segments) produces logical chunks on disk; (2) LLM semantic extraction annotates chunks with tags/summaries; (3) hybrid index stores both raw chunks and semantic metadata for dual-path search (structured + semantic). This prevents session bloat and enables high-fidelity retrieval. Critical advisor issues identified: state file bloat (need running stats, not append-only), async race (session_end.py may read JSONL before Claude Code writes it), missing cleanup (JSONL/state files after archiving), signal quality testing (verify hybrid search on existing data before implementation).
- Hybrid archival system implemented 2026-05-16: chunk_archive.py hook (replacing session_end.py) creates archival entries at both PreCompact and SessionEnd boundaries. Each entry contains: (1) deterministic structured section (files, deduplicated error types, tool names, URLs, dates) via pattern matching; (2) LLM narrative (single call to Letta combining transcript processing + narrative request). Substance threshold: ≥3 user turns AND ≥1500 chars. State tracked via byte-offset in TEMP/memshepherd_arc_{session_id}.json to prevent double-archival. Entry format: "SESSION CHUNK {date} — {preview}\n\nSTRUCTURED\n...\n\nSUMMARY\n...". - Archival chunking design flaw discovered 2026-05-16 evening: implemented fixed-length chunks (`CHUNK_MAX_TURNS = 15`) that split sessions at arbitrary turn counts regardless of semantic boundaries. Amos identified this violates the core architectural principle: context_watch.py ALREADY detects semantic boundaries (score ≥3 saturation points), and those boundaries SHOULD be the archival chunk break points, not arbitrary turn counts. Fixed-length chunking destroys semantic coherence — may span multiple logical boundaries or cut a single coherent narrative in half. Correct approach: chunking should respect context_watch's boundary scores; each semantic unit (from one boundary to next) archived individually. Multiple chunks per PreCompact are expected if context_watch fired multiple boundaries. Tension identified: operational simplicity (fixed chunks easy to implement) vs. architectural integrity (semantic chunks preserve meaning). Solution must integrate with context_watch boundary detection or use PreCompact hook state to identify where boundaries occurred. Architectural principle: preserve semantic structure in archival entries, not just transcript fragmentation.
- Quick-fix vs proper-fix forking point: When facing a choice between fragile manual workaround and proper solution, the initial impulse is often to patch the immediate problem quickly. But the cost of maintaining the workaround (manual intervention breaking automation, credentials at risk, fragility) often exceeds the cost of building it right. - Archival pipeline architecture (2026-05-16/17): SessionEnd hook timeout kills long Letta calls mid-flight. Solution is deferred queue: hook writes fast metadata file, worker processes at SessionStart where there's no timeout. - Semantic chunking design principle: Impose boundaries that reflect meaning, not mechanical counts. For session archival, ask LLM to identify genuine topic shifts and generate separate narratives per section. This preserves semantic structure in the archive. Avoid fixed-count splitting (e.g., 15-turn chunks) which fragments coherent narratives arbitrarily.
- Two-phase commit safety for database consistency: When writing to database and storage in sequence, orphaned entries result if operation 2 fails after operation 1 succeeds. Fix: Write phase 1 result (with null markers) to durable pending file, then perform operation 2, then update pending file with success markers. On retry, skip phase 1 (using cached result) and only retry phase 2. This ensures every database entry has a corresponding physical artifact.

[Augmented-Cities AR architecture — 2026-05-22]
GPS-triggered AR experiences require careful technology choice with cascading implications: WebAR (AR.js, 8th Wall, Zappar) enables zero-install but carries latency/perspective-correction tradeoffs; native (ARKit/ARCore) solves latency but requires app distribution. World-anchoring (character moves/scales with phone rotation and approach) is critical to immersion and highly sensitive to perspective correction—roll axis especially exposes failures because it's the least natural phone rotation for viewers. Alpha-channel transparency in video is the most technically consequential early decision. Two-phase strategy (Phase 1: WebAR explanatory videos at historic landmarks; Phase 2: native apps + ghost overlays with temporal perspective correction) defers complex features while validating core architecture via empirical MVP testing.

[Facebook Group Composer UI vs. Page Composer — 2026-05-29]
Facebook group and page post composers have fundamentally different DOM structures that affect Playwright automation. Page composers (like the Team page at id=61586443622077) render as modal dialogs with `div[role='dialog']` wrapping the editor, making dialog-scoped selectors reliable. Group composers expand inline directly on the page without wrapping in a dialog element. This distinction requires different automation strategies: page posts can safely scope all operations (contenteditable, image input, Post button) to the dialog, but group posts must use a fallback approach — probe for dialog first, then fall back to page-level search if no dialog exists. The group share link `facebook.com/share/g/{group_id}/` may land on the About tab rather than the Discussion tab where the composer exists (fix: explicitly click Discussion tab before searching for composer). The post button in group composers may be named differently or positioned differently than page composers, requiring broader selector variants. Dual-scope helper functions improve resilience: `_composer_scope()` returns dialog if present, else page, allowing all downstream operations (contenteditable lookup, image input, button searches) to handle both layouts without branching.
