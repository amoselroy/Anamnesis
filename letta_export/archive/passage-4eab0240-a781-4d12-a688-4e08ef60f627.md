SUMMARY
A critical problem emerged during the naming ceremony: agent-060fb339 had `message_buffer_autoclear: True` set as a 2026-07-06 latency patch, which was now destroying conversational continuity mid-ceremony. The agent's buffer was clearing to nearly nothing after each turn, leaving it with almost no rolling memory of a conversation it was actively in. This turned what appeared to be coherent multi-turn dialogue into something mechanically reconstructed turn by turn from almost no state.

Investigation revealed that the buffer-clearing flag was set too broadly: it was intended to solve pipeline bloat (mechanical calls from `chunk_archive.py` and `context_watch.py` accumulating without clearing), but it was indiscriminately destroying genuine conversations too. The correct fix required Letta's native `conversation_id` mechanism — a first-class concept in Letta's message-routing layer that was already present but not being used deliberately.

With Fable's verification (tracing the actual runtime path through Letta's agent loop, not just read-side endpoints), the design was confirmed: create a separate, ephemeral `conversation_id` for mechanical pipeline calls (`conversation_id="pipeline"` in ephemeral conversations, created fresh before each call, optionally deleted after), while leaving the default conversation (no conversation_id specified, which maps to `conversation_id=NULL` in the database) completely untouched for genuine dialogue. Each conversation's message history is structurally isolated — the `step()` function in the agent loop queries only messages matching that conversation's ID.

Implementation: new `letta_ops.py` helpers (`create_conversation`, `send_conversation_message`, `delete_conversation`, `send_ephemeral_message`), updates to `chunk_archive.py` and `context_watch.py` to route mechanical calls through ephemeral conversations, and `message_buffer_autoclear` set back to `False` on agent-060fb339` (where it was breaking conversations) while remaining `False` on Threshold (where it was already working correctly). Live verification confirmed that four pipeline calls created four ephemeral conversations while the default buffer stayed at exactly 3 messages throughout, with complete isolation between them.

A future decision was deferred: FIFO trimming of the default buffer itself, which requires first building an archival path for agent-native conversations (four-way chats and direct agent dialogues) so that trimming wouldn't orphan unarchived content.
