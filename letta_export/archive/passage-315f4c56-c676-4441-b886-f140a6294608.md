SUMMARY
Amos raised a critical design gap: when a new therapy is added, it may have no matching row in therapy_status table even if that drug already has regulatory/trial data in the agency_import table (from the monthly FDA/EMA/ANVISA/CT.gov CSV downloads). The slug mismatch isn't a problem because matching uses alias-based INN lookup, but the timing issue is: data is already imported but sync only runs monthly. Designed and implemented sync_therapy_from_existing_imports() function that runs immediately after create_therapy() or approve_draft(), queries existing agency_import rows, runs the same alias-based matching logic as the monthly monitor, and upserts therapy_status if a match is found. Guards against writing placeholder rows when no match found — correctly logs and exits cleanly for genuinely pre-clinical compounds. Implemented in parallel: added threading to therapies.py create_therapy endpoint, added function call to admin.py approve_draft endpoint. Amos correctly noted that in theory every therapy with clinical trials should already have a regulatory row (from CT.gov if nothing else), so no-match case indicates truly pre-clinical compounds, which is semantically correct state.
