WORLD PATTERN 2026-07-05 — Git-bypassing writes create invisible attribution corruption — 2026-07-05

PRINCIPLE: Writes that occur outside version-controlled code paths get invisibly folded into later commits, misattributing changes and breaking audit trails.

NARRATIVE: The sleeptime companion uses a plain `BlockManager` instance, not the git-backed variant. Its edits bypass the git commit layer entirely. However, MemShepherd's own writes use git-backed blocks and create commits with timestamps and attribution. When the companion modifies a block at T0 without creating a git entry, and MemShepherd later reads and writes that same block at T1 (to apply legitimate updates), the companion's T0 changes are folded invisibly into MemShepherd's T1 commit. An audit of what MemShepherd changed at T1 would show only MemShepherd's edits, not the earlier modifications that happened before the commit. The corruption compounds: the 560 runs of the companion across two months created 329 recorded edits across the blocks, but zero of them appear in git history with their true timestamps and causality. This pattern affects any system with multiple writers where some bypass version control: whether from agent logs, cron jobs, or external services, writes that don't create version-control entries corrupt the audit trail of writers that do, making it impossible to reconstruct what actually happened or who changed what. The fix requires all writers to participate in the same versioning mechanism, or accept that audit trails will be corrupted.
