WORLD PATTERN 2026-06-19 — Polling-based async operation completion detection with last_updated field — 2026-06-19

PRINCIPLE: When HTTP endpoints return immediately from background work, the client needs a polling mechanism to detect completion; using a naturally-updated `last_updated` field eliminates the need for separate status endpoints.

NARRATIVE: After converting long-running LLM endpoints to background thread execution (returning `{"status": "started"}` immediately to avoid gunicorn worker timeout), the UI had no way to know when the work completed. A user noted the button hung indefinitely. Solution: the JS polls the therapy API every 5 seconds, snapshots the `last_updated` value before triggering, then watches for that value to change. When the background job finishes and updates the database, `last_updated` changes, the poll detects it, and a completion toast fires with automatic table refresh. This pattern eliminates the need for a separate status endpoint by reusing a field that gets naturally updated by the operation itself. The approach scales: any entity with a `last_updated TIMESTAMPTZ` field can adopt this pattern without schema changes.
