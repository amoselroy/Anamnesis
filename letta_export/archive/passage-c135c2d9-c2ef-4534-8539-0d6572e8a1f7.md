WORLD PATTERN 2026-07-02 — Single process-wide lock serializes correctness better than per-unit claims — 2026-07-04

PRINCIPLE: When multiple processes write to shared state, protecting individual units (files, rows) does not protect the shared resources they all write to; a single system-wide lock makes protection exhaustive and non-negotiable.

NARRATIVE: Initial MemShepherd concurrency protection used atomic sidecar files to prevent two workers from claiming the same pending file. But the real hazard was three shared blocks (world/patterns, orientation, pins) that both workers write to via GET-then-PATCH operations. Two workers processing *different* files can race on the same blocks, with the second writer's PATCH silently erasing the first's updates. Protecting individual files is like locking seat assignments at a table while leaving the table itself unguarded. The fix was a single process-wide lock file (`_worker.lock`), such that only one `process_queue()` invocation can run at all, serializing all block writes by construction. This shifts the burden from "prevent collision at the unit level" to "only one worker touches shared resources at a time," making the protection exhaustive and obvious. The per-unit approach created the illusion of safety (workers were well-separated) while missing the actual hazard (shared resource collision).
