WORLD PATTERN 2026-06-18 — Soft-delete with re-attachment for curation safety — 2026-06-18

PRINCIPLE: When users curate content by deletion and automated systems later re-add deleted items, soft-delete with recovery capability prevents both the re-addition problem and accidental deletion of legitimate content.

NARRATIVE: During Braindexer news management, Amos identified an architecture problem: each Research run would re-add news articles previously deleted via the Manage News modal, because deletion was hard (immediate removal from database) and re-addition checked only for URL existence. The solution was soft-delete using a `deleted_at TIMESTAMPTZ` column: when a user deletes an article, the row remains in the database with `deleted_at = NOW()` set. The news fetch logic checks the full set of news URLs (including soft-deleted rows) for deduplication, preventing re-addition of deleted articles. The UI only displays rows where `deleted_at IS NULL`. This allows accidental deletions to be recovered by clearing the `deleted_at` timestamp — a critical feature since curating article lists is error-prone. The pattern extends beyond news: any scenario where automated systems might re-add content that humans have deliberately removed benefits from soft-delete with recovery, provided there's sufficient context to identify and recover deleted items.
