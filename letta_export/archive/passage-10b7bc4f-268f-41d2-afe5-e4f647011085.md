WORLD PATTERN 2026-06-20 — Cross-join artifact in diagnostic queries — 2026-06-20

PRINCIPLE: Analytical queries that join counting dimensions with the data being analyzed can unintentionally multiply results without error, masking actual data volume and misleading investigation.

NARRATIVE: When investigating the "315 duplicate papers" on Sauna therapy, the diagnostic script `diag_ranking.py` performed a cross-join between sources and conditions via therapy_conditions, multiplying 9 actual papers by 35 linked conditions. The result was 315 rows sent to Haiku, causing the LLM to return 315 scores for the same 9 papers repeated, producing scrambled tier assignments. The query was structurally valid SQL (no syntax error) but semantically incorrect — it counted combinations rather than unique entities. The issue only surfaced when comparing diagnostic output (315) to expected results. This pattern generalizes: when building diagnostic or analytical queries, joining observation counts with categorical/dimensional data requires careful awareness of whether the join multiplies results or merely associates metadata.
