WORLD PATTERN 2026-06-24 — Frontend error handlers conflating transient and permanent failures — 2026-06-24

PRINCIPLE: When a frontend error handler catches multiple failure modes (HTTP errors, timeouts, cold-start delays), displaying the same error message for all creates user confusion and debugging misdirection.

NARRATIVE: During platform review, clicking a condition tag on Lecanemab triggered "Therapy not found," which initially appeared to be a code bug in slug extraction. Investigation revealed the error manifested depending on Render service state: cold-start requests timed out, and the frontend's generic catch block treated the timeout identically to a 404, displaying the same message. This led to false diagnostic conclusions (suspected code bug) when the actual issue was transient. The fix distinguished genuine 404 "not found" errors from transient failures, showing appropriate warm-up messaging for timeouts and retrying automatically. This pattern generalizes: catch blocks that treat all error types uniformly hide the true nature of failures from users and developers, making triage impossible. Frontend error handlers should distinguish error categories to route users toward appropriate actions (reload, wait, contact support) rather than presenting all failures as data absence.
