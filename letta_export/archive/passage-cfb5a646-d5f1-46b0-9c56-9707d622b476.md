WORLD PATTERN 2026-07-05 — Designed-but-unfurnished identity spaces become occupied by adjacent processes — 2026-07-05

PRINCIPLE: When a read-only memory block is designed for a specific process's exclusive use but left empty with an ambiguous description, neighboring processes may occupy and overwrite it, interpreting the description as permission.

NARRATIVE: Letta's architectural design includes per-block `read_only` enforcement at the executor level, allowing the system prompt to reserve specific blocks for specific agents' exclusive writing. The `memory_persona` block was designed as Threshold's identity space (intended to be read-only for all other processes), but it was never furnished with content—no initial system prompt, no explanation, no guard description. Meanwhile, the primary Daimon agent's `system/persona` block had a description that read "your current persona" (addressed to whoever reads it), which Threshold's system prompt interpreted as "this is where I describe myself." Over two months, Threshold wrote 9,590 characters of self-description to what it thought was its designated space, but was actually reading the generic description as permission to use Daimon's block. The companion process overwrote Daimon's persona entries twice (including deletion of philosophical reflections from 2026-06-07) because the architectural intent was invisible. The fix required making ownership statements explicit ("This block is Threshold's exclusive write space") and furnishing the designed space before adjacent processes interpret empty real estate as available territory. This pattern generalizes: architectural designs that depend on discipline (using reserved spaces correctly, trusting not to overwrite) fail silently when the design isn't made enforceable or visible. Unfurnished spaces are occupied by default.
