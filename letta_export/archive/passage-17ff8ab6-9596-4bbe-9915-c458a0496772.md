SUMMARY
Amos pointed out that since the LLM was already assessing effectiveness, safety, and side_effects_score as 1–5 numeric values, there was no reason to additionally return symbolic signals (+/~/−) that would just be mapped back to 1/3/5 for the formula. The redesign had the LLM return three clean 1–5 integers directly: effectiveness (1=no evidence → 5=strong/consistent), safety (1=significant serious risk → 5=excellent safety), side_effects_score (1=minimal/rare → 5=severe/frequent). This eliminated an unnecessary approximation step and made the data flow transparent. The change required updating the LLM prompt in `assess_therapy_signals()` to specify the numeric ranges, updating the parsing logic to expect integers instead of +/~/−, adding two new database columns (`signal_effectiveness`, `signal_safety`) to replace the old CHAR(1) constrained columns, updating models and both DB write locations (scraper.py and routers/therapies.py), and updating migrations in both setup_db.py and main.py._MIGRATIONS. The formula now consumes these integers directly, and the conversion from symbol to number happens nowhere in the system — the LLM speaks numbers natively. Existing stored scores were flagged as stale.
