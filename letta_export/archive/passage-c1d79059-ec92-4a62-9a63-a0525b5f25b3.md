SUMMARY
The `backfill_news_dates.py` script encountered an `IndexError: list index out` when executing a parameterized SQL query. Investigation revealed two distinct issues: (1) bare `%` characters in the `NOT LIKE '%news.google.com%'` SQL clause were being interpreted by psycopg2 as format string placeholders (expecting parameter count to match), (2) the script output contained Unicode characters (→ arrow, em dashes) that Windows console codec (cp1252) couldn't encode when redirecting to a file. The first issue was fixed by escaping literal `%` as `%%` in the LIKE clause. The second issue was addressed more comprehensively by forcing UTF-8 encoding on stdout at the script start with `sys.stdout.reconfigure(encoding='utf-8')`, which eliminates character-by-character encoding conflicts. The fix pattern learned: psycopg2 uses `%s` for parameters and requires literal `%` to be doubled, and Windows console output redirection requires explicit UTF-8 reconfiguration to handle any Unicode character in dynamically generated output (article titles, etc.). PostgreSQL and the browser handle UTF-8 natively, so the constraint is purely local diagnostic tooling.
