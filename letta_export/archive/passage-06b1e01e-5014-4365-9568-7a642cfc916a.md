WORLD PATTERN 2026-06-19 — Abstract fetching deferred to manual per-entity operations for cost control in batch LLM workflows — 2026-06-19

PRINCIPLE: When enriching LLM context with expensive secondary data (abstracts, details), fetch it during deliberate manual operations (Rank Papers) rather than automatic background jobs (Research), keeping pipelines fast and cheap while preserving accuracy on demand.

NARRATIVE: Early discussion suggested fetching abstracts for all papers during research runs to improve Haiku's relevance scoring from title-only to title+abstract. However, this would add one PubMed API call per paper, increasing API call volume, token usage, and execution time for every research run. The solution: implement abstract fetching only in the Rank Papers endpoint—a deliberate, manual per-therapy action where cost is acceptable. Research runs stay fast and cheap; users who want better scoring run Rank Papers explicitly. Implementation added `_fetch_pubmed_abstracts()` as a batch call (all PubMed IDs in one request), included first 500 chars in the Haiku prompt, then discarded (no storage overhead). Non-PubMed sources continue title-only. This pattern applies broadly: expensive secondary context should be fetched on-demand for precision, not as a default for every run. The tradeoff is explicit: users trade latency for accuracy only when they choose to.
