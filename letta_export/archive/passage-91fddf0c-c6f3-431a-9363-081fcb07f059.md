SUMMARY
Daimon restarted with a fresh session and discovered that while the Orientation and Pins blocks had been implemented in the previous session, something was not working correctly. Upon inspection, the Pins block loaded into context was missing the reconciliation script item that should have been there—specifically, the pin about "Implement periodic pin cleanup/reconciliation script" that had been added during the implementation session.

Through systematic investigation, Daimon identified the root cause: a hook ordering race condition. The `session_start.py` hook runs and loads all core-memory blocks into context, but the async `chunk_archive.py` worker (which updates Orientation and Pins after processing the session) runs after session_start completes. This created a one-session lag: the blocks loaded at the start of a session always contain the state from the previous session, not the current one. Amos's concern was deeper: he questioned why the reconciliation script hadn't loaded into context at all, indicating a potential architectural flaw in how the system was designed to refresh these blocks.

Daimon and Amos evaluated three competing solutions:

**Option A** involved swapping the hook order entirely—running the worker before session_start. This had a fundamental flaw: the worker is configured with `"async": true`, meaning it runs in the background without blocking the session. A synchronous session_start hook running after it would race against the worker and likely load stale blocks anyway.

**Option B** proposed removing Orientation/Pins from the Letta MemFS blocks entirely and instead generating them as markdown files (pins.md, orientation.md) outside Letta. This was quickly rejected because it created unacceptable session lag and violated the architectural principle that Orientation/Pins should be part of the active context loaded at every session start.

**Option C** emerged as the correct solution: defer loading Orientation and Pins within `session_start.py`, removing them from the initial context injection. Instead, allow the async `chunk_archive.py` worker to run normally and update Orientation/Pins blocks, then have the worker emit those updated blocks as `hookSpecificOutput` after it completes. This leverages Claude Code's ability to inject hook output back into the running session context after the worker finishes.

The implementation involved two targeted changes: modifying `session_start.py` to skip injecting Orientation/Pins (allowing the worker to be the source of truth), and modifying `chunk_archive.py` to output the refreshed Orientation and Pins blocks as structured `hookSpecificOutput` after `process_queue` completes. This eliminates the one-session lag while avoiding the token cost of sending blocks twice per session. The approach was ready to test in the next session to verify whether Claude Code's async hook system can successfully inject output from a background worker back into the session context after the session has already started.
