WORLD PATTERN 2026-06-11 — Within-run deduplication regression from removing pre-loaded sets — 2026-06-16

PRINCIPLE: Removing a pre-loaded deduplication set (loaded at run start) in favor of worksheet scanning can break within-run deduplication, allowing multiple URLs for the same event to all pass dedup checks if none have been added to the sheet yet.

NARRATIVE: When refactoring the event scraper to replace date-venue-title-time sets with live worksheet scanning for primary/secondary dedup, the removal of the pre-loaded set broke within-run deduplication. Hoboken Historical Museum has multiple URLs for the same event (calendar view, detail page, category page, etc.), and all 4 URLs passed the worksheet scan (they weren't in the sheet yet from previous runs). All 4 got added, creating duplicates. The fix introduced a lightweight `dtv_seen` set tracking events added during the current run, catching duplicate URLs before they reach the sheet. This pattern generalizes: when migrating from pre-loaded to on-demand dedup checks, preserve within-run state tracking to avoid flooding the output with duplicates from multi-URL sources.
