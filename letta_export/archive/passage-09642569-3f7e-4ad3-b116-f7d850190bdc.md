WORLD PATTERN 2026-06-11 — Single HTTP round-trip per entity when scraping multiple related fields — 2026-06-11

PRINCIPLE: When scraping a detail page to augment API data with multiple related fields, fetch the page once and extract all fields from that single request rather than making separate requests per field.

NARRATIVE: After discovering that ICTRP's API returns truncated country lists, the initial design would have made a separate HTTP request just to get the full countries. Extended design recognized that the same detail page contains three related pieces of information (countries, contact details, enrollment form URL), so a single `_scrape_trial_detail_page(url)` function was built to extract all three fields in one parse operation. This reduces latency and bandwidth compared to three separate requests, and scales better when the scraper runs across many trials. The pattern generalizes: when augmenting API responses with scraped detail data, batch the scraping — one page visit per entity to extract all needed augmentations.
