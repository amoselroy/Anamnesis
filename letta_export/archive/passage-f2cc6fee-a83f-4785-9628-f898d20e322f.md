WORLD PATTERN 2026-06-19 — Backfill migration for retroactive population of new schema columns — 2026-06-19

PRINCIPLE: When adding a new required column that must be populated from existing data or constant values, use a migration statement to backfill before any code attempts to read the column.

NARRATIVE: After adding `shown_condition_ids` and `excluded_condition_ids` columns to the sources table, existing articles had empty arrays, making them invisible under the new opt-in visibility model. A migration was added to populate existing articles with all of their therapy's active conditions, making them immediately visible without requiring a re-fetch. This applies broadly: whenever you add a NOT NULL or constrained column to an existing table, a backfill migration bridges the gap between old state and new expectations. Without it, either the schema migration blocks startup (if you add NOT NULL without default), or you get unexpected empty/null values in production code that depends on the new column being populated.
