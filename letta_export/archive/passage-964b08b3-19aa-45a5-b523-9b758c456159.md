SUMMARY
During implementation of the consolidated status table, the relationship between raw regulatory monitoring (`ct_phase: PHASE3`) and curated display level (`evidence_level: phase3` or `approved`) required clarification. The user noted apparent duplication: why maintain both `therapy_regulatory_status.ct_phase` and `therapy_conditions.evidence_level` when they overlap? The solution refined the distinction: raw monitoring data (FDA approved, EMA status, CT.gov phase) should automatically update the display `evidence_level` without requiring curator confirmation — this is objective fact. However, curator confirmation remains essential for `withdraw` and `discontinue` which have operational consequences. Implementation added `_sync_evidence_level()` function that runs during each monitor pass: if FDA or EMA shows approved status, set `evidence_level = 'approved'` (no curator step); otherwise set `evidence_level` from best available CT.gov phase; don't touch it if no regulatory match (preserves manual entries like lifestyle interventions marked `observational`). This pattern prevents stale display values while reserving curator discretion for consequential state changes.
