WORLD PATTERN 2026-07-05 — Fire-and-forget async tasks outliving their API calls — 2026-07-05

PRINCIPLE: Async tasks triggered within API handlers continue executing after the handler returns, creating unbounded race windows for concurrent writes to shared state.

NARRATIVE: Letta's sleeptime companion runs as a fire-and-forget asyncio task spawned during the agent's inference, executing `BlockManager.update_block_async` calls after the REST API call has already returned to the caller. The companion reads block state, computes changes, and writes back over multi-second windows (extended-thinking latency ~15s), while the only concurrency guard—the optimistic-lock `version` column—protects only milliseconds inside a single DB session, not the full read-modify-write span. Last write wins silently; concurrent writes from MemShepherd's own snapshot operations, Daimon's recovery batches, and the still-enabled companion produced data-loss incidents (68 pins erased, persona block clobbered, duplicate pins injected) because the unsynchronized race had multiple seconds to play out. The pattern generalizes: any post-return async execution in a multi-writer system is a concurrency hazard, particularly if the async work involves semantic reasoning (LLM calls) with variable latency. Detection requires either tracing execution context or finding ghost writes with no corresponding recent code changes.
