WORLD PATTERN 2026-06-25 — Staging table population as prerequisite for downstream sync operations — 2026-06-25

PRINCIPLE: In periodic reconciliation systems with multiple stages, downstream operations that depend on staging data must either ensure staging is pre-populated or handle graceful early-exit when staging is empty.

NARRATIVE: sync_therapy_from_existing_imports reads from the agency_import staging table populated by the monthly agency monitor job. When Render deployed a fresh environment, agency_import was empty because the monitor had never run. The sync function executed without error (correct design — it guarded against empty agency_import by returning early), but produced no therapy_status rows because it had no data to match against. This wasn't a crash; it was silent non-operation. The requirement for agency_import to be pre-populated is a hidden dependency not surfaced anywhere except in the code itself. The pattern applies broadly to ETL-like systems where multi-stage operations exist: each stage should either pre-populate its upstream dependencies, document what must be pre-populated, or include diagnostics that clarify why it produced no output. The silent success-with-no-output is the failure mode to prevent.
