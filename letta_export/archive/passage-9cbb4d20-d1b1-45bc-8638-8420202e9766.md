SUMMARY
The session began with Matrix room confirmation and identification of a critical cross-script contamination issue: `fb_poster.py` had been loading a `facebook_session.json` that was in page-actor context (Hoboken NJ Real Estate page) after `re_poster.py` ran and saved the session while acting as the page. This prevented `fb_poster.py` from posting to the Hoboken Connection group, which requires personal account context.

The root cause was session file sharing between the two scripts. The fix involved separating session files: `fb_poster.py` now uses `facebook_session_personal.json` (dedicated personal account session), while `re_poster.py` continues using `facebook_session.json` (page-actor context). A fresh login was required: running `fb_poster.py --login` created the clean personal session file, and subsequent event and exhibition posts began landing correctly on the group feed.

Additionally, a dual-workbook bug was discovered and fixed: `get_pending_events()` and `get_pending_exhibitions()` each loaded the spreadsheet separately, causing exhibitions to overwrite event marks before they were persisted. The fix unified workbook loading so a single workbook object is passed to both functions, preventing data loss during the save phase.
