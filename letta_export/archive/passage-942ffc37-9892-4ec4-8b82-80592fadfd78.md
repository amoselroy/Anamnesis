Amos pivoted to Braindexer, noting that while therapy discovery should have been scraping for new entries, nothing had happened. Investigation revealed the Braindexer server wasn't running on Render. The discovery mechanism relied on APScheduler running inside the FastAPI process (scheduled for Sunday 3 AM), but with Render's free tier, the server spins down on inactivity. When cron-job.org pings awakened it, the APScheduler restarted with a fresh clock and almost certainly missed its Sunday 3 AM window every week. The original plan was for cron-job.org to maintain server uptime through regular pings but not to actually trigger the scraper — the triggering was supposed to happen via APScheduler internally. This meant discovery was entirely dependent on the server happening to be alive at 3 AM on a Sunday, which was not happening. Amos clarified that cron-job.org was only set up for keepalive pings, not enabled for actual scheduling yet. The solution designed: add HTTP endpoints (`POST /admin/run-discovery` and `POST /admin/run-monitor`) secured with the curator key, allowing cron-job.org to directly call them on a schedule rather than relying on APScheduler. This decouples the schedule from server uptime — the server can sleep normally and wake once per week when cron-job.org hits the endpoint. Daimon proposed this as cleaner, cheaper on Render free hours, and making the schedule explicit and visible rather than buried in config.
