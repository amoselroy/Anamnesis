SUMMARY
Amos raised a design question: when an experimental compound like MK-2214 eventually receives a brand name from regulatory approval, how should the system ensure the public-facing drug name gets updated rather than relying on a human to notice? This triggered a broader discovery: the codebase had a database table `status_suggestions` and working backend code to automatically detect three categories of regulatory changes (FDA/EMA approval, withdrawal, phase transitions) and log them as pending alerts, but no corresponding web UI had ever been built to display those alerts. This is a classic instance of "documented architecture without runtime enforcement" — the detection mechanism was complete and working, but the human decision-gate for acting on it was silently missing, leaving all historical regulatory changes sitting in the database invisible to any curator.

The solution built was two-tiered: (1) a new fourth suggestion type `rename` detected from two sources — agency imports comparing the agency's registered trade name against known therapy names, and a source-grounded LLM check during research runs asking whether the scraped papers/news show a distinct brand name — and (2) the missing admin UI panel ("Regulatory Updates" tab) to surface all four suggestion types for human review and approval. When a suggestion is confirmed, the appropriate update happens (for rename, the therapy's `name` field updates to the brand name while the old code name is preserved as a `therapy_aliases` row so literature searches remain effective). Schema changes included widening the `status_suggestions.suggestion_type` CHECK constraint to include `'rename'`, with the migration added to both `setup_db.py` and `main.py._MIGRATIONS` per the project's redundancy convention. The detection function `_detect_brand_name` was grounded in actual sources, mirroring the earlier condition-detection fix. End-to-end testing confirmed the pipeline (insert suggestion → list in admin UI → confirm → therapy renamed + old code name preserved as alias). The implementation was committed and pushed. This work surfaced not just the missing feature but the existence of three previously-invisible suggestion types that had been accumulating data without any curator ever being aware of them.
