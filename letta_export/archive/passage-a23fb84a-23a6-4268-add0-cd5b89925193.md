WORLD PATTERN 2026-06-19 — NULL database values bypass Python dict.get() default fallback — 2026-06-19

PRINCIPLE: When a database column is nullable, `dict.get('key', default)` returns `None` if the key exists but holds NULL, bypassing the fallback entirely; defensive code must account for this asymmetry.

NARRATIVE: The research pipeline crashed silently on Gamma Sensory Stimulation when `_build_context()` called `therapy.get('mechanism', '')` intending to fall back to an empty string if mechanism was missing. However, Gamma's mechanism column was NULL in the database. Python's dict.get() treats a missing key differently from a key with a None/NULL value: when the key exists in the dict but maps to None, the fallback is ignored. Calling `.strip()` on the None value crashed the thread. The fix was `therapy.get('mechanism') or ''`, which handles both missing keys and NULL values correctly. This pattern applies universally to databases with nullable columns: defensive coding must either (1) use `or` chaining, (2) explicitly check for None, or (3) ensure the database layer converts NULL to empty string before populating the dict. The pattern recurs in any system bridging ORM/database layers to Python where NULL is represented as None.
