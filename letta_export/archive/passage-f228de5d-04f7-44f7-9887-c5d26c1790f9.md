WORLD PATTERN 2026-06-11 — API summary fields often truncated, complete data available at referenced URL — 2026-06-11

PRINCIPLE: When an API response includes both a summary/truncated field and a reference URL to a detail page, the complete/untruncated version of that data is typically available by scraping the referenced detail page.

NARRATIVE: ICTRP's API returns a `<Countries>` field with abbreviated country lists for large multi-country trials, particularly when the full list would be very long. However, the same API response includes a `web_address` field linking to the trial's detail page on the registry. The actual detail page renders a full "Countries of Recruitment" section with the complete list. Rather than trying to parse or reconstruct the full list from the abbreviated API response, the solution was to follow the reference URL and scrape the complete data from the HTML. This recognizes that APIs often provide summary representations for efficiency (smaller JSON payloads, faster responses), while the authoritative complete data lives in the detail view that the API references. This pattern applies across many APIs and data sources: when you encounter a truncated field with a reference URL, assume the complete data is at the reference and scrape if needed.
