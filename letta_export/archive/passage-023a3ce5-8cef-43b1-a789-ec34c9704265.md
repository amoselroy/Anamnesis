SUMMARY
Diagnosed why `run_agency_monitor()` endpoint returned `{"status":"started"}` but never actually populated `agency_import` table. The core problem: both admin endpoints used `daemon=True` background threads, which get killed when Render's free tier spins down the process after 15 minutes of inactivity. The FDA zip file (~30 MB) and ANVISA CSV (~100 MB) downloads take 5-10 minutes, far exceeding the idle window. The thread would die mid-download, leaving nothing in the database. This manifested as "status: started" responses that never resulted in any data. Solution implemented in two parts: (1) Created per-agency endpoints (`/run-agency-monitor/{agency}`) that run synchronously (each agency < 3 minutes, safe on Render), returning `{"status":"done", "summary":{...}}` when actually complete; (2) Created local runner script `run_agency_monitor_prod.py` that connects directly to production Neon DB and runs monitor synchronously on user's machine, bypassing Render entirely. Updated admin panel button to call per-agency endpoints sequentially with visual progress indicators. Amos ran the local script successfully (FDA OK, EMA OK, CT.gov OK) in just a few seconds, confirming the architecture works and data lands in production DB immediately.
