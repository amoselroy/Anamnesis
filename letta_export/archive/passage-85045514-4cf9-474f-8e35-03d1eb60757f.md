WORLD PATTERN 2026-06-09 — Entry point context determines information architecture — 2026-06-09

PRINCIPLE: When the same entity can be accessed through multiple paths (e.g., search within a category vs. direct browsing), the information structure and data requirements may differ and should be reflected in separate UX flows rather than unified display.

NARRATIVE: Braindexer therapy pages needed to serve two distinct user intents: (1) "I'm researching therapies for Alzheimer's" (condition-first entry, expects condition-specific summaries and scores immediately), and (2) "I found this therapy called Lecanemab, what is it?" (entity-first entry, wants a unified view across all conditions first, then can drill into condition-specific details). Attempting to serve both flows with a single page design created information overload and confusion about which condition's data to display. The solution: two distinct UI templates — a generalized therapy view (accessed directly, shows all conditions as selectable chips) and a condition-specific therapy view (accessed from condition search or chip selection, shows data for that condition). This pattern generalizes: any time a resource can be discovered through different discovery paths, ask whether the entry path implies different information needs, and if so, make that distinction explicit in the UI rather than trying to unify them.
