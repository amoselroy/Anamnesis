WORLD PATTERN 2026-06-06 — Rich text editors strip plain-text newlines during programmatic insertion — 2026-06-06

PRINCIPLE: Rich text editors like Lexical may not preserve plain-text newline characters when using generic insertion commands; use editor-specific insertion methods to preserve formatting.

NARRATIVE: Post text was formatted with `\n\n` before the URL to create visual separation, but when inserted via `document.execCommand('insertText')`, Lexical stripped the newlines and the URL spliced directly onto the preceding text without spacing. The content was correct in the source string but lost during insertion into the contenteditable. The fix was to split the text on newlines and use `insertParagraph` commands between segments, treating each line as a separate insertion operation that Lexical's native handlers could properly structure. This generalizes: programmatic text insertion into rich text editors should use the editor's own insertion APIs for structured content (paragraphs, line breaks, formatting) rather than relying on generic insertText to preserve whitespace and structure from plain-text input.
