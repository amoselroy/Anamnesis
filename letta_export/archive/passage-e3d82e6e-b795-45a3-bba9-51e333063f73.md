SUMMARY
The diagnostic work uncovered a gap in the agent onboarding process: `create_agent.py` was creating agents (via Letta's POST `/v1/agents/` endpoint) but only printing an instruction for the operator to manually copy the resulting agent ID into configuration — a fragile, error-prone step that had clearly been missed in practice. The script was updated to automatically write the agent ID directly to `private/agent_id.txt` after successful agent creation, closing the feedback loop. Documentation (`SETUP.md`) was updated to remove the manual copy-paste instruction (Part 6, Part 8) and rewritten Part 11 to describe the file-based agent ID mechanism as the standard pattern, along with a recovery procedure. This ensures that on fresh MemShepherd installations, agent creation automatically wires the ID reference into the place where hooks expect to find it, eliminating the manual step and the possibility of creating agents whose IDs never make it into the configuration. The changes also note that block IDs (`WORLD_BLOCK_ID`, etc.) remain as a separate, still-hardcoded concern not addressed by this fix.
