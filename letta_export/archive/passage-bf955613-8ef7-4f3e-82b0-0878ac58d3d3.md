WORLD PATTERN 2026-07-02 — Widening analytical frame reveals design-invisible bugs — 2026-07-04

PRINCIPLE: A bug in a design is often invisible from the vantage point that produced the design; examining beyond the artifact that changed finds failures at integration boundaries.

NARRATIVE: During MemShepherd hook refactoring, Daimon initially proposed a per-file claim mechanism to prevent two concurrent `chunk_archive.py` workers from processing the same pending file. An independent review caught that this protected the wrong resource — two workers can process *different* files and still both write to the *same shared blocks* (world/patterns, orientation, pins) with a classic lost-update race. This hazard only became visible when the frame widened from "protecting files" to "protecting all resources these workers touch." Only after the first fix was deployed did a follow-up reveal that `world_trim.py` — a separate script — was independently writing to the same shared blocks with zero awareness of any lock mechanism. Each incremental fix was invisible from the narrow frame it occupied, but visible only when examining the entire synchronization landscape. This generalizes: when a design solves a problem, scrutinizing the immediate solution reveals only that narrow success; catching integration failures requires asking "what else touches these same resources" rather than "is this fix correct."
