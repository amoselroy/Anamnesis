SUMMARY
A spot check of returned articles revealed relevance issues: many articles had tangential connections to the therapy (sidebar mentions, passing references). Initial instinct to add a title-filter (requiring therapy name in headline) was rejected by Amos, who recognized that human-in-the-loop curation via the delete button was the right mechanism and that relevant substantive articles not mentioning the therapy in the headline would be lost. This led to four parallel improvements: (1) remove the title filter entirely; (2) add a `sentiment` column (CHAR(1) with values `'+'`, `'-'`, `'~'`) to be assessed by a single batch LLM call per therapy; (3) sort news articles by `published_date DESC NULLS LAST` with newest first; (4) extend news display to the informed (intermediate) view, not just layperson. A batch sentiment function `assess_news_sentiment()` was implemented that passes all article titles in one prompt to Haiku, receiving back a JSON array of sentiment characters — cost-efficient, no per-article API calls. The function includes defensive error handling, normalizing unexpected values to `'~'` and padding if necessary. All changes were implemented together: updated `setup_db.py` with the sentiment column, added sentiment assessment to the router endpoints and scraper, updated `models.py` with the new field, and modified `therapy.html` to render sentiment badges (colored circles: green `+`, red `−`, gray `~`) next to each headline, with news appearing in both layperson and informed tabs. The human curation mechanism (delete button in "Manage News" modal) remains the primary quality control, allowing users to remove articles the automated system couldn't perfectly distinguish as irrelevant.
