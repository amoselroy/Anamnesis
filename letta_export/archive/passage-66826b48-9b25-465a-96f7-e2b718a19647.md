WORLD PATTERN 2026-06-10 — Unguarded external API calls prevent fallback execution — 2026-06-10

PRINCIPLE: When an external service call (like an API for embeddings or translations) is made before fallback logic, and that call fails, the entire operation fails even if the fallback would succeed.

NARRATIVE: The search endpoint called `embed()` to get query vectors for semantic similarity search as the first operation in the function. If Voyage AI was unreachable or the API key was missing, the function threw a RuntimeError and returned 500 immediately, before the code could reach the keyword search fallback that would work fine without embeddings. The fix was to wrap `embed()` in a try/except, set `query_vector = None` on failure, and allow execution to continue to the keyword search path. This is distinct from general error handling — the issue is **order of operations**. External service calls should either come after fallback logic is established, or be wrapped such that their failure doesn't prevent the entire execution from continuing. The pattern recurs whenever a system has a primary path that depends on external services and a secondary path that doesn't — the external call should be guarded so that its failure doesn't prevent the secondary path from running.
