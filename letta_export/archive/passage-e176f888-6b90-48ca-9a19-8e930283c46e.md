WORLD PATTERN 2026-08-11 — Re-fetch verification after apparent timeout on remote state updates — 2026-08-11

PRINCIPLE: When an API operation appears to timeout, don't assume failure; re-fetch the target state to verify whether the operation succeeded server-side.

NARRATIVE: During pins reconciliation work, PATCH operations repeatedly appeared to timeout while subsequent re-fetch confirmed the writes had actually succeeded. This revealed a critical tactical pattern: timeout indicates lost client-server connection, not necessarily server commit failure. In distributed systems, the client and server operate asynchronously; a timeout can mask successful operations. The solution is simple: when timeout occurs on an idempotent or commutative operation, re-fetch the actual state rather than trusting the error signal. This prevents false loss evidence and allows systems to proceed confidently rather than treating every timeout as potential data loss. Applies broadly to any scenario where external API operations can succeed server-side despite connection loss.
