SUMMARY
Research on Gamma Sensory Stimulation was failing consistently with two distinct failure modes: initial runs hit PubMed 429 (Too Many Requests) errors, and later runs showed Neon SSL connection timeouts and ICTRP 403 Forbidden errors. Investigation of Render logs revealed the root cause: Gamma Sensory Stimulation has 6 aliases (including "40 Hz sensory stimulation," "gamma frequency stimulation," etc.), and the `research_therapy()` function was making 2 PubMed API calls per alias sequentially but with no inter-request delay, resulting in 12 requests hitting PubMed's free-tier 3 req/second limit within seconds. Every call returned 429, so the scraper inserted zero new sources. The initial fix added a 0.4-second delay between PubMed calls, which kept the request rate under 3/sec. However, a deeper solution emerged: NCBI offers free API keys that bump the rate limit from 3 to 10 req/sec. Amos registered an NCBI API key and added it as `NCBI_API_KEY` to Render environment variables. The code was already prepared to read this env var and pass it to PubMed requests automatically (anticipated by prior implementation). This fully eliminated the rate limiting problem. The session also surfaced that ICTRP's XML API was returning malformed XML (likely HTML error pages instead of valid XML), which was caught by try/except but left trial registration results empty — this was deprioritized as a lower-impact issue (news and PubMed carry the main results). The rate-limiting architecture insight: when a therapy has multiple aliases and each fires multiple API calls, sequential execution without delays will trigger rate limits; inter-request delays or API key upgrades are the practical solutions.
