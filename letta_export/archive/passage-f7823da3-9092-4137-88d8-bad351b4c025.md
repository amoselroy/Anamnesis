WORLD PATTERN 2026-06-18 — Schema migrations must run automatically on deploy — 2026-06-18

PRINCIPLE: Database schema changes should execute automatically as part of the deployment process, not as manual operations run separately, to prevent production databases from diverging from application code.

NARRATIVE: The HTTP 500 on the drafts page was caused by the production Neon database missing four columns that existed in the application code's `setup_db.py`. The migration script existed and was idempotent (all statements used `IF NOT EXISTS`), but it was never executed on production because Render's startup only runs `uvicorn`. This meant the schema could drift arbitrarily between local dev (where `setup_db.py` runs) and production. The fix was adding `preDeployCommand: python setup_db.py` to `render.yaml`, making migrations part of the automatic deploy pipeline. This is safer than manual migration steps because: (1) it's guaranteed to run before the application starts expecting the schema; (2) idempotent migrations can be safely re-run; (3) no human step is required. The pattern applies regardless of database or deployment platform — schema changes and application code must deploy together, or the database becomes a source of silent failures.
