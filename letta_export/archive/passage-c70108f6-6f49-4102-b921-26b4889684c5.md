After the cleanup decisions, the session investigated the remaining problematic sources. **Hudson County Chamber**: 33 local Hudson County events exist on the site, but the location filter drops them all because venues lack city/zip tags — solution is to whitelist `business.hudsonchamber.org` domain as trusted geo-scope. **Hoboken Recreation (RecDesk)**: Initially appeared to be a connection-refused issue blocking all scrapers, but when Amos tested the URL directly (`hoboken.recdesk.com/Community/Calendar`) it loaded fine — revealing that the site specifically blocks non-browser requests. Playwright can reach it but returns 0 links because RecDesk renders events as clickable `<div>` elements with `onclick` attributes or `javascript:` handlers, not `<a href>` anchor tags that the scraper's link collector looks for. The listing-page LLM fallback then fails with `"Extra data: line 2 column 1"` because the LLM returns an empty array `[]` followed by explanation text, causing `json.loads()` to fail. **Eventbrite JC**: A broad Eventbrite search returning mixed local/regional events; venues have no city field attached, so location filter drops everything. Solution: trust the source URL's inherent geo-scope (`jersey-city` in URL) without requiring venue-level tags. **General JSON parsing bug**: The LLM listing extraction can return empty results with trailing explanation text, breaking JSON parsing globally. A one-line fix was identified: strip any trailing text after the closing `]` bracket before attempting `json.loads()`.
