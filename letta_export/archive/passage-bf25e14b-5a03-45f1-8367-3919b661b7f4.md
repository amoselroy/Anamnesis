SUMMARY
After the `onFilterChange()` fix was deployed, users reported that search was still failing with a 500 error. Diagnostic investigation revealed the root cause was not in the condition filter logic but in the search endpoint itself. The `search_therapies()` function was calling `embed()` (Voyage AI embeddings) as the first operation without error handling. If `BRAINDEXER_VOYAGE_KEY` wasn't set on Render or if Voyage AI was unreachable, the function would throw a RuntimeError and return 500 before the keyword search fallback could execute. The fix wrapped `embed()` in a try/except block, setting `query_vector = None` on failure and allowing the search to fall through to keyword-based similarity matching using SQL `LIKE` clauses. Local testing confirmed the new code returned 200 OK with graceful degradation. Additionally, a SAVEPOINT fix was applied to `_resolve_condition_slug()` to prevent transaction abort contamination (a secondary hardening measure identified from the previous session). Both fixes were committed and Render redeployed successfully.
