WORLD PATTERN 2026-06-05 — Playwright keyboard input requires pointer-focus state — 2026-06-06

PRINCIPLE: JavaScript-only focus() on contenteditable elements does not establish the internal focus state needed for Playwright's keyboard.type() to deliver input.

NARRATIVE: When automating rich text editors, setting focus via page.evaluate(js_click_and_focus) followed by keyboard.type() appears to work (logs execute, no errors) but input never reaches the visible composer. The disconnect occurs because Playwright's keyboard simulation maintains its own internal focus state independent of the DOM's focused element. JS focus updates the DOM but not Playwright's internal state, leaving keyboard input routed nowhere. Only actual pointer interaction (click or force=True click) establishes both simultaneously. For editors where pointer clicks are blocked by overlays, document.execCommand('insertText') bypasses both systems entirely, inserting at the DOM level.
