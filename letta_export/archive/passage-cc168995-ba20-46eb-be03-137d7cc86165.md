WORLD PATTERN 2026-06-18 — Promise.all() masking individual promise failures in dependent UI components — 2026-06-18

PRINCIPLE: When Promise.all() wraps multiple promises and one fails, the entire composition rejects, preventing dependent UI from rendering even the successful results.

NARRATIVE: In the Manage News modal, `_loadNewsModalContent()` used `Promise.all([activeArticles, deletedArticles])` to load both active and soft-deleted news articles. When the deleted-news fetch failed (missing route, auth error, or DB error), the entire Promise.all rejected, causing the modal body to error and hide both sections — even though the active articles had fetched successfully. This made it appear that nothing was soft-deleted rather than surfacing a specific error. The user saw a broken modal instead of an error message explaining what happened. The fix was to decouple the promises: fetch and render active articles first, then fetch and render deleted articles independently with its own error boundary. If deleted-news fails, a fallback message ("Could not load removed articles: <error>") appears in the Removed section without affecting the active list. This pattern applies broadly: when multiple async operations feed independent UI regions, avoid Promise.all() for the entire composition. Instead, resolve each section independently with its own error handling, so a failure in one region doesn't cascade to collapse the entire interface.
