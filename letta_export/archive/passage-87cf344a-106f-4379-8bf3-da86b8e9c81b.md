SUMMARY
Jersey City Theater Center (JCTC) initially returned 0 events despite 9 links being found. Root cause analysis revealed a structural path problem: JCTC's actual events live on a third-party ticketing platform (`seetickets.us/jctcenter`), but `get_event_links` rejects cross-domain links, leaving only 9 navigation pages (`/history`, `/past-performances`, etc.) with no event data. Path A failed on all nav links; Path B didn't trigger because the link count (9) exceeded the fallback threshold (< 4); Path C's Playwright also found the same incorrect nav links. Implemented two architectural fixes: (1) modified `use_listing_fallback` to trigger when ALL found links failed extraction (`all_failed` condition), not just when links < 4 — this allowed Path B (LLM extraction on the listing page) to rescue the situation and extract 3 events; (2) added a safety net after Path C's detail loop to also fall back to LLM if all Playwright-fetched links failed. Additionally, created a new dedicated `Path ST` (seetickets ticketing) that uses Playwright to fetch individual event detail pages (avoiding the static fetch timeout issue) — similar to the earlier Eventbrite path. Replaced JCTC's URL with `seetickets.us/jctcenter` and Path ST extraction improved results from 3 to 7 events (with 8 filtered by `min_date`). These changes generalize beyond JCTC: the `all_failed` fallback benefits any source that returns nav/content pages instead of event pages, and the Path ST pattern provides a template for other JS-heavy ticketing platforms. Investigation clarified why Playwright alone doesn't solve domain-mismatch problems: Playwright executes JavaScript to render dynamic content, but if the actual event data lives on a different domain (not just dynamically loaded), JS execution doesn't help — the LLM fallback succeeds because it reads page content as text, independently of link structure.
