SUMMARY
Amos requested building an event scraper for the JC and Hoboken events that was previously running on Tasklet.ai. After reviewing the pseudocode, the architectural challenge became clear: 44 heterogeneous event sites with no standard schema.org JSON-LD structure. Rather than relying on a single extraction method, a layered hybrid approach was designed: Path A (static HTML with CSS selectors/regex for sites with consistent structure), Path B (Claude Haiku LLM for listing pages when A yields nothing), and Path C (Playwright for JavaScript-rendered sites when both A and B yield 0). This approach balances cost (Haiku only on hard cases, ~$0.01-0.03/night) with reliability (guaranteed extraction across all 44 sites). The event_scraper.py was built to write directly to the local xlsx at `C:\Users\Amos\Documents\My Google Docs\Social\JC and Hoboken Events.xlsx`, following the same pattern as fb_poster.py, reading the "Events Primary Sources" sheet for the rotation list and writing event results to "Pending Posts". The key architectural decision: images would be handled at post time in fb_poster.py rather than in the scraper, eliminating stale URL issues and simplifying the scraper's responsibility to just "source" (URL provided) or "none" (blank, triggering Pexels fallback at post time).
