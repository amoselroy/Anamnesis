WORLD PATTERN 2026-06-11 — Schema changes without production migration causing cascading failures — 2026-06-11

PRINCIPLE: A database schema change defined in migration scripts but not executed in production will cause silent 500 errors in dependent features, cascading across multiple code paths that depend on the new column.

NARRATIVE: The `pathway_tags` column was added to `setup_db.py` schema definition for `therapy_conditions` but the migration was never run on the live Neon database. When the refactored `get_therapy` endpoint tried to SELECT this column for condition-filtered views, PostgreSQL threw an `UndefinedColumn` error, resulting in a 500 that the frontend caught and displayed as "Therapy not found." The general browse page worked fine because it never queries condition-specific data. The failure was compound: a schema definition gap that didn't break anything immediately, then a feature (condition filtering) that depended on that schema, making the gap visible only when that specific code path was exercised. This pattern generalizes: schema changes must be executed on all environments, not just defined in migration scripts, or dependent features will fail silently in production while working in development. The cascade nature — one missing column breaking multiple downstream queries — makes these failures particularly difficult to diagnose.
