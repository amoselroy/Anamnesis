WORLD PATTERN 2026-06-17 — Enumerate on filtered collections gives wrong indices for sparse source data — 2026-06-17

PRINCIPLE: When filtering a list from a source with gaps (empty rows), enumerate produces sequential indices (0, 1, 2...) that don't match the source's actual row numbers, causing writes to stamp the wrong rows.

NARRATIVE: The event poster filtered events from a spreadsheet using `enumerate(_sheet_rows())`, which produced sequential numbers starting from 0. However, the worksheet contained 150+ empty rows between rows 667 and 820. So `enumerate` index 0 was actually spreadsheet row 667, index 1 was row 668, etc. The poster stamped "Posted At" timestamps into the wrong (empty) rows rather than the actual event rows, meaning every posted event would be re-posted the next day as unmarked. The fix: iterate the source directly via `ws.iter_rows()` using actual row indices rather than relying on enumerate on a filtered output. This pattern generalizes to any system that filters from a source with structural gaps — enumerate will always give you sequential indices that don't map back to source positions.
