WORLD PATTERN 2026-06-22 — Bulk monitoring vs. inline checks — architectural efficiency pattern — 2026-06-22

PRINCIPLE: One-time periodic queries to external sources with diff-based detection is architecturally superior to inline checks distributed across repeated operations.

NARRATIVE: When designing monitoring for regulatory status changes, the initial instinct was to check therapy status inline during the research loop (which already runs for each therapy). However, this creates 3×N API calls where N is the number of therapies, plus it couples unrelated concerns. A bulk monthly monitoring job that queries each agency once and diffs against a stored snapshot reduces to 3 total calls, catches therapies not yet in the catalog, and cleanly separates regulatory monitoring from research/papers/news functions. The insight generalizes: whenever you're checking for external state changes across multiple entities, consider whether one-time periodic bulk queries with snapshot comparison is more efficient than per-entity inline checks, especially when the check operation has cost (API calls, network, processing) and the change frequency is predictable (monthly, quarterly).
