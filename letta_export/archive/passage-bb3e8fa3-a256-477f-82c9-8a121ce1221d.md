SUMMARY
Identified that ICTRP's API returns truncated country lists for large multi-country trials because the `<Countries>` field is a summary string rather than a complete list. However, the full "Countries of Recruitment" section is available on the linked ICTRP trial registry detail page. Designed and implemented a comprehensive solution: created `_scrape_trial_detail_page(url)` helper function that performs a single HTTP round-trip per trial to scrape the detail page and extract three critical pieces of information not fully captured by the API: complete country list, contact information (both Public and Scientific contacts), and enrollment form URLs. Extended the scraper to capture both `Public_Contact` and `Scientific_Contact` from the ICTRP XML (removed the early break that was preventing dual capture), and serialized contacts as semicolon-separated entries in the notes field with format `Contact: name — email · phone; name2 — email2`. Updated the frontend `activeTrialsHtml` function to parse and render multiple contacts on separate rows with clickable `mailto:` and `tel:` links, plus a green enrollment form link when present. The implementation is backward-compatible with existing single-contact trial records. Updated the manually-seeded Lecanemab trial (source ID 82) with two contacts and a phone number to verify the multi-contact rendering layout. All changes are designed to auto-activate when the ICTRP API is fixed and a real scrape is triggered — the scraper will capture both contact types, enrollment form links, and full countries without code changes needed.
