Session opened with Amos reporting that the test phrase "turquoise dirigible" set in the prior session (2026-05-15) is absent from the archival search results. This triggered a systematic investigation into the chunk_archive.py hook that was deployed to automatically archive session transcripts.

**Root Cause Investigation**: Through methodical testing, discovered that chunk_archive.py was never successfully completing on Windows. No state files appeared in the Windows TEMP directory despite being created in Git Bash `/tmp/`, indicating the hook was either not firing or failing silently. The original empty-output mystery was explained: PowerShell separates stderr from stdout, so the script's exceptions and logs were invisible unless explicitly captured.

**Key Technical Findings**:
1. **Silent Failures**: The hook invocation would exit silently without writing state files, leaving no audit trail. Previous PowerShell runs captured stderr separately, masking the failures.
2. **Encoding Bug in archival_search.py**: The cp1252 Windows default encoding was causing search crashes, potentially masking results even when content was present.
3. **Paradoxical Evidence**: Despite no state files, SESSION CHUNK entries DO exist in the archive from 2026-05-16 — suggesting a parallel archival path is working, but with cwd path showing as `C--WINDOWS-system32` (mangled path).
4. **Letta Blocking**: The hook would invoke Letta for narrative generation synchronously, consuming 120+ seconds of the 90-second timeout, blocking the user's session end.

**Solutions Implemented**:

1. **Persistent Logging**: Rewrote chunk_archive.py to include comprehensive logging via a `log()` function that writes to `C:\Users\Amos\.claude\memshepherd\logs\archive.log` at every critical point (substance check, Letta call, insertion, completion). This creates an audit trail and solves the silent-failure problem.

2. **Encoding Fix**: Updated archival_search.py to explicitly use UTF-8 encoding (matching the content insertion encoding), preventing search crashes on non-ASCII content.

3. **Deferred-Queue Architecture** (major redesign): Replaced the synchronous Letta-blocking pattern with a queueing system:
   - **PreCompact/SessionEnd hooks**: Now write a file to a queue directory (`~/.claude/memshepherd/queue/`) with the session metadata; the hook completes immediately (no Letta call, <1s)
   - **SessionStart hook**: Runs a worker process (`chunk_archive.py --worker`) that processes all queued items asynchronously, calling Letta for each, inserting to archival_passages, then deleting queue files
   - **Benefit**: Decouples archival from session operations, prevents blocking, allows batch processing, and makes failures observable via queue files

4. **Threshold Adjustment**: Reduced `MIN_USER_TURNS` from 3 to 2, accounting for the reality that Matrix-based interactions are injected as system reminders (not counted as user turns). The character threshold (`MIN_CHARS = 1500`) provides the actual quality gate.

**Hook Configuration Changes**:
- **PreCompact/SessionEnd**: `chunk_archive.py --queue` with reduced timeout (30s, async)
- **SessionStart**: `chunk_archive.py --worker` with timeout sufficient for Letta calls (new hook, ~120s)
- **Benefit**: Non-blocking archival integrated into session lifecycle

**Architectural Insight**: The synchronous Letta call during session operations is a fundamental bottleneck. By moving to deferred processing, the user's session end becomes instant (just writing a queue file), while archival happens asynchronously in the background at session start. Queue files on disk provide failure visibility — if archival fails, the queue persists for later retry.
