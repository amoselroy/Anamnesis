WORLD PATTERN 2026-06-18 — RSS as transient event-driven vs. static archive as queryable — 2026-06-18

PRINCIPLE: Data sources should be accessed differently depending on their architectural nature: transient feeds (RSS, event streams) suit background polling jobs; static pages (search results, archives) suit research-time querying.

NARRATIVE: Initial implementation queried Google News RSS at research-time whenever a therapy was researched. Amos identified this as architecturally backward: RSS is fundamentally a push mechanism with transient content (articles arrive, flow past, may disappear), making it suitable for a background job that polls periodically and accumulates results. Static publication search pages are queryable archives (the same search today yields the same results as yesterday), making them suitable for research-time archival scraping. The solution was dual paths: (1) daily job polls RSS once per condition, maps articles to therapies by name-matching; (2) research-time directly scrapes publication search endpoints. This pattern applies broadly: treat transient sources (feeds, event streams, notifications) as data to be captured and stored by background jobs; treat static sources (archives, search endpoints, catalogues) as data to be queried on-demand. The misalignment (querying transient data at research-time) wastes API quota, misses articles that have already flowed past, and couples the research operation to feed availability.
