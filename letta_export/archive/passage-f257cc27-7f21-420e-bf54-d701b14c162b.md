WORLD PATTERN 2026-06-23 — Concurrent process execution via inadequate restart procedure causing duplicate posts — 2026-06-23

PRINCIPLE: Restarting a process without explicitly killing the original instance creates a race condition where both instances read the same unposted rows and post them simultaneously before either can mark rows as completed.

NARRATIVE: FB Poster hung mid-operation while posting to Facebook (process waiting on Playwright submit that never completed). When manually relaunched to continue from the next row, the original hung process was never explicitly killed. For a brief window, two instances were running: the hung process slowly recovering from its Playwright wait, and the new process reading unposted rows from the spreadsheet. Both read rows 915-920 as "not posted" and both posted them. Neither had written the "posted" mark yet when the other process read, so duplicates occurred. The fix is to explicitly kill any existing process before relaunching. This pattern generalizes to any system with shared mutable state (spreadsheet, database, file) where multiple instances of the same process could compete for work: always verify the prior instance is dead before starting a new one. The cost is small (one process kill command) and the failure cost is high (data duplication, wasted operations, inconsistent state).
