WORLD PATTERN 2026-06-10 — Double requestAnimationFrame ensures CSS transition fires reliably — 2026-06-11

PRINCIPLE: Using two consecutive requestAnimationFrame calls guarantees that a CSS transition will fire, by forcing a paint cycle before the transition class is added.

NARRATIVE: Implementing page entrance animations required fading in the therapy cards after the logo appeared. A single `setTimeout(0)` or `requestAnimationFrame` to add the transition class was unreliable — sometimes the transition would fire, sometimes it wouldn't, depending on browser timing. The solution was to use two requestAnimationFrame calls: the first ensures the element is painted with its initial invisible state, the second adds the transition class and triggers the animation. This works because the first frame forces a render-tree update, making the second frame's class addition a visible state change the browser recognizes as animatable. This pattern generalizes to any CSS transition that needs reliable triggering from JavaScript.
