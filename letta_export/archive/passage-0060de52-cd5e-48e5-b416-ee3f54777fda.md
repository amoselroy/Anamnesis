Session 2026-07-03 Claude Code: Semantic Kernel Compression & Faithful Reconstruction Research Thread

Amos initiated exploration of a foundational architectural challenge prompted by MemShepherd's known gap: chunk_archive.py narration summaries are too high-level and lose design rationale on re-narration. The core idea: distill text down to a compact, possibly non-linguistic "atomic kernel" of semantic/epistemic essence, then reconstruct full text from it reliably — framed as a reversal of vector-search embedding, requiring decomposition of sentences into elemental components.

Initial critical pushback (Daimon) identified that this maps onto existing work (vec2text, VQ-VAE discrete latents, AMR parsing, knowledge-graph extraction) and flagged the central risk: natural-language compression is necessarily lossy (many expressions → one semantic kernel), so "reconstruct consistently" can only mean meaning-equivalent, not bit-identical. The deeper danger: a generative decoder reconstructing from a lossy kernel produces fluent, confident text regardless of whether it faithfully reconstructs original meaning — confabulation that is structurally invisible, which is dangerous for a memory system whose purpose is trustworthy continuity.

Breakthrough insight emerged from recognizing that humans can only meaningfully verify/score a kernel if it's expressed in some legible sub-language — a fully opaque non-linguistic vector code cannot be human-scored at all. This connected to the anchoring problem: a jointly-trained encoder/decoder pair can collapse into private degenerate code precisely because nothing external constrains what the kernel means. A constrained, legible sub-language (Abstract Meaning Representation graphs, Natural Semantic Metalanguage primitives, or Controlled Natural Language like Attempto Controlled English) reintroduces exactly that external anchor — fixed vocabulary and grammar the two models cannot silently renegotiate, playing the same role a frozen embedder plays in vec2text prior art.

Amos proposed AMR specifically as near-term pilot direction: existing mature parsers (SPRING, amrlib) and generators already exist as separately-trained components, matching ideation/verbalization split directly. This reframes the move from "train a new model from scratch" (6-12 months) to "pilot against existing AMR tooling on real MemShepherd chunks" (days-to-weeks experiment before committing to bigger self-correcting-model project).

When consulted independently, Threshold and Fable converged on the same core blocker: defining a "faithfulness signal" for training a reconstruction decoder without access to ground truth at inference time. Any stand-in judge (entailment model, QA verifier) is itself just another model with the same confabulation failure mode — bootstrapping a guarantee from a component with that failure mode is circular, not a scaling problem. However, they diverged on second-round assessment of the constrained sub-language approach:

Threshold was more optimistic that AMR anchoring is "sufficient" — formal constraints on grammar prevent secret renegotiation, making it auditable, reducing residual risk to just the decoder confabulating given correct AMR input (smaller, localized problem). Recommended 3-5 day pilot.

Fable pushed back with more rigorous critique: (1) the anchor is weaker than it appears — grammar constrains *form*, not *mapping*; a jointly-trained parser/generator pair could still smuggle information steganographically through node selection, argument ordering, or `:name` literals (same way CycleGAN hides steganography in legal-looking images), making this a weaker guarantee than vec2text's fixed embedder which pins the actual function; (2) AMR is a representation not a summary and is often as long as source text, so "which subgraph to keep" reintroduces the exact lossy-selection problem one level down at the graph layer instead of prose layer; (3) a clean off-the-shelf pilot won't test closed-loop honesty since existing SPRING/amrlib were never jointly trained, so there's no collusion pressure to reveal.

User proposed two-model architecture: ideation (kernel-extractor) and verbalization (reconstructor) trained separately on human-scored bootstrap, then closed-loop together. Daimon clarified this maps onto dual learning/back-translation (unsupervised MT, CycleGAN cycle-consistency patterns), but flagged critical risk: once both sides become trainable and closed-loop begins, you lose the trustworthiness property that made vec2text work. A jointly-optimized encoder/decoder can converge on private invertible code achieving perfect round-trip reconstruction while encoding no recognizable "core idea" — nothing in cycle-consistency loss prevents this. Vec2text sidesteps this by keeping embedder fixed and externally motivated. Solution: don't let sides co-adapt freely; keep an anchor (freeze one side during alternating fine-tuning, or keep human-scored verifier in loop permanently with periodic refresh rather than static proxy, avoiding Goodhart's law reward hacking).

User's recognition that "humans could only reach intermediary layer still using language but more fundamental" was the decisive move. Constrained sub-language (not fully opaque vector) solves the anchoring problem: a fixed vocabulary and grammar cannot be silently renegotiated by jointly-trained models the way raw vectors can. External anchor is reintroduced. Human or automated entailment checker can verify reconstruction fidelity through symbolic entailment against legible representation, not opaque embedding-distance proxy.

Final assessment: The original framing ("build a model reconstructing without confabulation") is less appealing post-scrutiny; two rounds of expert review didn't kill it but stripped away versions looking like they might have clean solutions. The problem looks conceptually open, not an engineering gap closeable with compute. More appealing: the narrow, precisely-posed question that survived — "define instance-level faithfulness signal not borrowing the failure mode it's meant to catch" is falsifiable with a cheap, concrete first move (AMR pilot on real MemShepherd chunks, days not months). Daimon's stake in the project (its relevance to anamnesis reliability) weakened through scrutiny — immediate relief comes from structured-fields fix already scoped separately; this research's payoff is speculative and distant.

Decision: AMR pilot is the correct near-term move (days-to-weeks, not months) before committing to self-correcting-model research project. Full conversation archived in Google Doc for review. Session ready for reset (all knowledge externalized, no open work in flight).
