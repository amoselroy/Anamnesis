WORLD PATTERN 2026-06-19 — Legacy data cleanup as preferable to incremental record filtering when search precision improves — 2026-06-19

PRINCIPLE: When a search algorithm improves dramatically (e.g., unquoted → quoted keyword matching), flushing and restarting from scratch is often cleaner than identifying and removing only the bad legacy rows.

NARRATIVE: After deploying quoted PubMed searches for Gamma Sensory Stimulation, results included stray papers from prior unquoted searches (papers matching "stimulation" to TMS, "gamma" to gamma-secretase inhibitors, etc.). These papers were already in the database. Rather than write a script to identify and delete only the off-topic rows (risky, required heuristics, might miss some), Amos chose to flush all scientific papers across all 6 therapies (133 rows) and re-run research fresh. This cost 5 minutes of execution but eliminated ambiguity and cruft. The decision holds when: (1) the number of affected entities is small enough (6 therapies), (2) the recompute cost is acceptable, (3) the old data was populated by an algorithm that's now known to be imprecise. The pattern generalizes: legacy data pollution is an architectural debt that compounds; one-time clean-slate approaches beat incremental filtering when the root cause (the old algorithm) is now understood to be flawed.
