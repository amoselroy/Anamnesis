SUMMARY
Discussion of block injection sizes revealed that the world/patterns block had grown to 20,720 characters despite a previous architectural redesign that was supposed to conserve space by separating full narratives into a Neon archival database. Investigation showed that while the archival infrastructure (spillover archive DB) exists, the actual operation to enforce the differentiation — separating one-liner principles (for the live block) from full three-level narratives (for archival) — was never implemented as an ongoing hook. The design intent is documented in the world/patterns block itself but not actually enforced. Critical discovery: the trimming operation must happen at **SessionStart**, not SessionEnd, because the sleep-time agent's output is only available when the next session begins. The proper flow is: SessionStart → fetch world/patterns (with new sleep-time entries) → split full narratives from one-liners → patch live block with compact version → queue full narratives for Neon archival → *then* inject blocks to session. A new standalone script was designed to perform this operation before `session_start.py` runs, using the backup-first pattern (timestamped logs), async queuing for Neon inserts (consistent with chunk_archive), and dry-run mode for safety before hooking into the chain. This addresses the gap between documented architecture and actual implementation.
