SUMMARY
The session opened with a report that the RE promo task failed to post on Friday (June 6). Investigation revealed the task had actually posted on Thursday (June 5) at 10:17 AM instead. The root cause: the "FB Promo Poster" task's trigger was anchored to a start boundary of May 29 (a Thursday), which overrode the intended `DaysOfWeek: Friday` setting. Weekly triggers in Windows Task Scheduler anchor to the day of week of the start date, so despite the config saying Friday, all runs fall on Thursdays. The fix requires updating the start boundary to a Friday (June 13) to shift the weekly cadence. During this investigation, two related issues surfaced: (1) the `fb_poster.log` in the project directory was stale (last entry May 27), but this was discovered to be an old backup — the code had been changed to write to the temp directory (`C:\Users\Amos\AppData\Local\Temp\fb_poster.log`), which is active and shows successful runs that morning; and (2) both "FB Event Poster" and "FB Exhibition Poster" tasks were found to be disabled. When I re-enabled them, Amos clarified that he had intentionally disabled them because they were duplicates of other scheduled tasks doing the same work. I re-disabled them. This investigation revealed that the project's logging had been silently migrated from the project folder to the system temp folder without updating documentation, creating a false impression that posting had stopped.
