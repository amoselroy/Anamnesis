NARRATIVE SUMMARY:

The session opens with a critical diagnostic: the "turquoise dirigible" canary phrase set in a prior session (deliberately not written to memory files) is absent from archival search. This triggers a comprehensive investigation into the chunk_archive.py pipeline.

**Root Cause Discovery**: The hook was calling Letta inline during SessionEnd to generate narratives, but the hook timeout (90 seconds) was shorter than the actual Letta call duration (120+ seconds). The process was killed mid-flight with no state file written and no archival entry created — a silent failure with no visible error log.

**Encoding Bug**: archival_search.py was using default Windows cp1252 encoding on UTF-8 output from psql, causing UnicodeDecodeErrors. Fix: explicit `encoding="utf-8", errors="replace"` on subprocess calls.

**Deferred Queue Architecture**: Rather than fix the timeout (which is fragile), the entire hook architecture was redesigned. SessionEnd hook now writes a fast `.pending.json` file (<1 second) without calling Letta. A new worker process runs at SessionStart, processes the queue, calls Letta there where there's no timeout pressure, and inserts archival entries. This decouples the session operation from the slow narrative generation.

**Logging Infrastructure**: The old system wrote to stderr which was invisible in PowerShell. A persistent log file (`~/.claude/memshepherd/logs/chunk_archive.log`) was added to every critical section, providing an audit trail of what happened in each hook invocation and worker run.

**Key Testing Finding**: Testing confirmed the deferred queue works end-to-end — file queued in <1 second, archived in 42 seconds, searchable at score 0.55. The full pipeline is now measurable and observable.
