After the migration issue was resolved, articles fetched before the opt-in system was deployed remained invisible because they had empty arrays (`shown_condition_ids = '{}'`). A backfill migration was added to populate existing articles with all of the therapy's active conditions, making them immediately visible in the Manage News modal without requiring a re-fetch. Additionally, the UPSERT pattern used in `update_news` was adjusted to not depend on the unique index on `(therapy_id, url)` — instead of relying on `ON CONFLICT`, the code now performs an explicit SELECT to check whether a row exists, then either INSERT or UPDATE accordingly. This change increased robustness in cases where duplicate URLs might exist from earlier multi-fetch runs before the unique index was created. The net effect: existing articles appear immediately, new fetches accumulate correctly across multiple conditions, and no articles are silently dropped due to constraint violations.
