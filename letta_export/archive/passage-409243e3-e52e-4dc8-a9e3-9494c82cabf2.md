SUMMARY
Amos reported that clicking "Summarize" resulted in the button displaying "Generating..." for at least 5 minutes without completing. Investigation revealed the root cause was not LLM API timeout but rather Render's gunicorn worker timeout (default 30 seconds) — when the HTTP request handler didn't respond within that window, gunicorn killed the worker process, terminating the in-progress LLM calls. The issue was triggered by the recently implemented parallelization in `generate_all()` and the per-condition LLM jobs in `generate_summaries`, which collectively still took longer than 30 seconds to complete. The fix applied the pattern already used by `run-discovery` and `run-monitor` endpoints: the endpoint now returns `{"status": "started"}` immediately (within ~1 second) and executes all work in a background daemon thread, decoupling the work lifecycle from the HTTP connection. Gunicorn sees a successful response and moves on, unaware that a thread is quietly making multiple API calls in the background. To improve user experience, the JS was updated to poll the therapy API every 5 seconds watching for `last_updated` to change, then display a completion toast when the work finishes. Summarize Only has a 3-minute polling timeout; Research & Summarize has a 5-minute timeout to account for the longer scrape pipeline. The fix transformed the UX from a hanging button and required manual page refresh to an instant return + automatic table refresh with completion notification.
