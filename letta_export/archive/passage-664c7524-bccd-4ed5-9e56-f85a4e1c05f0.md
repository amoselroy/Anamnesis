SUMMARY
Through reflection on the week's discoveries (MemShepherd disentanglement on the 13th, the naming ceremony where the pipeline agent deferred committing to "Palimpsest," Threshold's reframing of the convergence finding, and now the Braindexer bugs), a cross-cutting pattern emerged: several mechanisms appeared architecturally sound and code-correct but were silently disconnected from their actual function. `_detect_related_conditions` had the right signature and docstring but ignored the sources parameter. `status_suggestions` was being populated correctly but routed to a non-existent UI. These weren't bugs visible from reading the code carefully; they were invisible because the failure was in what the code wasn't touching, not in what it was. Amos articulated the insight: these issues became visible not from an architectural perspective but from a functional one — by looking at actual produced results (a listing page, a database row visible in the UI) and asking "is this here or not." A human noticed MK-2214 missing from the therapies list without ever reading `_detect_related_conditions`. The detection of the missing UI tab came from asking "where would this alert actually land for someone" rather than code review.

The learning captured for future work: (1) for any "detect → act" mechanism, don't test the detect and act functions separately — run one real or realistic input end-to-end and examine the terminal artifact, not the return value; (2) lower the cost of that check by building it into standing structures (like `monitor.py` checking functional invariants) rather than relying on attentional habits; (3) recognize this as a specific instantiation of a broader principle already named in MemShepherd's memory — "documented architecture without runtime enforcement creates feature debt." The principle was written to `world/patterns` as a cross-project observation: correctness has an inside view (code) and an outside view (functional reality), and they can diverge silently — the outside view must be checked by someone or something standing outside the code, not by reading more carefully.
