SUMMARY
With Opus as advisor, the discontinued/approved therapies feature design was refined through three key discussions. The DB inflation concern was clarified: the `discontinued` flag itself adds zero rows (just a status flip); inflation would only occur if proactively scraping historical failed compounds, which Amos decided against. Regarding the constraint naming concern, a direct query to the live Neon database confirmed that Postgres constraint names matched exactly as expected (`therapies_status_check`, `therapies_evidence_level_check`), eliminating the need for a complex DO block migration. Opus surfaced the Aduhelm case as a critical edge case: a therapy that was FDA-approved in 2021 then withdrawn from market in 2024 would simultaneously carry `approved_by=[{agency:"FDA", year:2021, withdrawn_year:2024}]` and `status='withdrawn'`, requiring careful UI design to render both the approval history and current unavailable status. Two additional design refinements emerged: the public search needs inline "Discontinued" tags for therapies found through the toggle; admin UI should enforce that evidence_level='approved' requires at least one approved_by entry. The design was validated as sound and ready for implementation.
