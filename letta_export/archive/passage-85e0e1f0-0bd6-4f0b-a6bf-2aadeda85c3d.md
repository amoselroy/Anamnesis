SUMMARY
While running recovery batches, Daimon noticed the live orientation block had been clobbered with stale June 11 content, and additional duplicate pins appeared in the live pins block—neither originating from the recovery script itself. This triggered deeper investigation into the Letta agent configuration and revealed a critical system component that had been running silently and autonomously the entire time: a sleeptime companion agent attached to the primary agent, triggering `frequency: 1` (after every single message), with full write access to all six shared memory blocks.

Fable's deep investigation of Letta's source code (`sleeptime_multi_agent_v4.py`, `block_manager.py`, `orm/block.py`) uncovered the core concurrency hazard: the companion runs as a fire-and-forget asyncio task that keeps executing *after* the REST API call returns to the caller. It calls `BlockManager.update_block_async` (same function MemShepherd uses), but the only concurrency guard—an optimistic-lock `version` column—protects only milliseconds inside one DB session, not the multi-second LLM read-modify-write window where the companion reads stale block state, computes changes, and writes back without any visibility into what else might have changed. Last write wins, silently, with zero error. Additionally, the companion uses a plain `BlockManager`, not the git-backed variant, so its edits bypass the git commit layer entirely—they're later folded invisibly into MemShepherd's own commits, misattributed.

Complete audit of the companion's 560 runs (329 recorded edits) across two months revealed four distinct data-loss incidents: (1) 2026-06-24, pins block fully rewritten, 68 of 75 entries erased; (2) 2026-06-08, entire `system/persona` block replaced with the companion's own self-description (titled "Keeper," then renamed "Threshold" 11 minutes later), erasing Daimon's identity-grounding entries including two 2026-06-07 reflection entries recording the decision to keep the name Daimon; (3) 2026-05-28, partial pins wipe; (4) 2026-07-06 during Amos's own recovery batches, orientation block clobbered with stale content and 19 stale duplicate pins injected, because sleeptime was still enabled when recovery messages triggered companion runs. Additionally, anamnesis exporter had an outage from 2026-06-10 to 07-01 (session_sync.py encoding bug), creating a blind spot where no exports captured either the legitimate content or the losses.
