SUMMARY
Discovered that the `condition_aliases` table did not exist in the production database because a stale Windows user environment variable was causing local `setup_db.py` runs to target the wrong database endpoint. When the therapies router tried to use `_resolve_condition_slug` which queries the missing table, it threw an `UndefinedTable` error (shown to users as "Therapy not found"). Multiple fixes were applied: (1) added defensive error handling to `_resolve_condition_slug` so missing table gracefully falls back to direct slug lookup instead of crashing; (2) ran `setup_db.py` directly against the correct production URI to create the table; (3) updated all three entry points (`setup_db.py`, `diag_db.py`, `diag_conditions.py`) to use `load_dotenv(override=True)` so the `.env` file always takes precedence over system environment variables, preventing this issue in the future. The fix ensures Render's own environment variables (stored with `sync: false` in the dashboard) are always the source of truth for production, while `.env` serves as the local development fallback.
