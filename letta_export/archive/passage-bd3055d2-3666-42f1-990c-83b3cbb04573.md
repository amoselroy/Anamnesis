WORLD PATTERN 2026-06-19 — Prompt instruction wording precision determines fundamental output structure — 2026-06-19

PRINCIPLE: Small changes in instruction phrasing ("Structure your entire response using X" vs. "After your main summary, append X") cause the LLM to interpret the requirement entirely differently, altering what content is included vs excluded.

NARRATIVE: After implementing structured summary sections (Effectiveness, Safety, Side Effects), the deployed output was completely wrong: only the three sections appeared with no main summary text. Investigation revealed the `_SECTION_INSTRUCTION` prompt said "Structure your **entire** response using exactly these three headers" — which the LLM correctly interpreted literally as "that's all there is; output only these sections." Changing one phrase to "After your main summary, append" reversed the interpretation: the LLM now wrote the full summary first, then added the three sections below. This wasn't ambiguous phrasing being disambiguated; it was tight phrasing being clarified. The lesson generalizes: instruction words like "entire," "only," "structure" vs. "append," "add," "include" fundamentally change how LLMs parse the requirement scope, and testing with actual LLM output (not reading the prompt in abstract) is essential before deployment.
