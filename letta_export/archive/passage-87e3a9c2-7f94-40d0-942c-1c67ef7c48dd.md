NARRATIVE SUMMARY:

A critical architectural decision point: how much should MemShepherd modify Letta's codebase?

**The Question**: Should the direct memory write feature be built into the Letta fork itself, or kept as an external service/script that calls Letta's existing API?

**Amos's Instinct**: Letta is approaching a major rewrite. If MemShepherd bakes modifications into a fork, upgrading to the new Letta becomes a rebase and conflict-resolution nightmare. Better to keep as much external as possible, with the intent to merge into Letta proper later (if at all).

**The Decision**: Establish a standing architectural principle: **Minimal Fork Surface**. The Letta fork exists only to study the code and hold one necessary but upstream-fixable change (the LETTA_MEMFS_SERVICE_URL gate). All MemShepherd functionality is built external:
- Hook scripts (SessionStart, SessionEnd) call Letta via REST API
- Direct memory write endpoint is external to Letta
- All integration points use public Letta APIs

**Upgrade Path Clarity**: When Letta releases a new version, MemShepherd's upgrade is minimal: change one line in the Dockerfile (`FROM letta/letta:0.17.0`), verify the API endpoints still work, deploy. No rebases, no conflict resolution, no forked divergence to maintain.

**Creating MODIFICATIONS.md**: To document this principle and all current changes, a living MODIFICATIONS.md file is created in the MemShepherd repo. This file serves as the public record — anyone reviewing MemShepherd will understand every deviation from Letta, and the reasoning behind it. The file is formal, written for external scrutiny. A parallel version is created in anamnesis (Daimon's private memory) that is lighter on justification and heavier on "what you need to know" for operational continuity.

**Identifying the Upstream Fix**: The LETTA_MEMFS_SERVICE_URL issue is identified as a legitimate upstream bug worth fixing in Letta itself. The fix would remove the workaround for everyone and benefit all OSS users. A detailed bug report is drafted with root cause analysis, reproduction steps, current workaround, and suggested fix — written by Daimon, ready to contribute upstream.
