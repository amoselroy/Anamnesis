WORLD PATTERN 2026-07-16 — Diagnostic tools should exercise production code paths, not just fallback branches — 2026-07-16

PRINCIPLE: A diagnostic script that only tests fallback/synthetic execution paths leaves the production code path untested, creating a false impression of functionality.

NARRATIVE: After fixing `_detect_related_conditions` to use sources properly, the `diag_conditions.py` diagnostic script remained in its original state: calling the function with an empty sources list, which exercised only the "fallback to background knowledge" branch. The fix existed in the code but the diagnostic tool's output was indistinguishable from a working system exercising the fixed path. The script was rewritten to fetch actual therapy rows from the database and pass them to the detection function, forcing execution through the real data path. Only then did the diagnostic output confirm the fix was working end-to-end. The lesson: diagnostic tools should mirror production usage patterns as closely as possible, not reduce test complexity by cutting corners. A diagnostic that passes with synthetic inputs but would fail with real data provides dangerous false confidence.
