WORLD PATTERN 2026-06-11 — Primary source overwrite architecture for credit attribution in aggregator feeds — 2026-06-16

PRINCIPLE: When primary venues and aggregator sources both list the same event, mark them as primary/secondary in the source configuration and implement in-place worksheet overwrites when a primary finds an aggregator-sourced row, ensuring primary venues get credit in the event record.

NARRATIVE: Initial approach of running aggregators last in rotation proved fragile — aggregators could still run first in a given cycle and own the event write. The solution adds a `Type` column to source configuration (primary/secondary) and a `Source Type` column to event records. When `_build_row()` processes a new event, it scans the worksheet for a `(date, time, venue)` match; if found and that row was sourced by a secondary source, the row is updated in-place rather than treated as a dupe. This ensures that when the actual venue's page scrapes its event later in the week, it claims the record. The pattern generalizes to any multi-source scraping where some sources are aggregators: explicit source typing plus live overwrite logic provides finer control than rotation ordering alone, and enables fair credit attribution to primary sources.
