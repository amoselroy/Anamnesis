WORLD PATTERN 2026-06-22 — Synchronous operation chains constrained by infrastructure sleep deadlines — 2026-06-23

PRINCIPLE: When background jobs run on platforms with automatic sleep windows, all retries must complete synchronously within one wake-up cycle, forcing aggressive timing and simplified retry logic.

NARRATIVE: Render's free tier automatically sleeps dynos after 15 minutes of inactivity. Initial monitoring job design used APScheduler's DateTrigger to schedule retries 6 hours later if agencies failed — pattern that works on traditional servers but fails on Render because the process is gone by then. Redesign: three synchronous retry attempts with 3.5-minute spacing (4+3.5+1+3.5+1 = ~13 minutes total), all within one dyno wake-up. Admin notification flag set immediately on first failure, cleared if any retry succeeds, stays set if all three fail. This approach trades sophistication (no distributed retries) for reliability: guaranteed execution within physical constraints. The pattern applies to any ephemeral platform with forced sleep: fit the entire operation (work + retries) into the guaranteed execution window, or make it retriggerable from outside (HTTP endpoint) rather than relying on internal scheduling.
