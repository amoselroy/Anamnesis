WORLD PATTERN 2026-06-04 — Single oversized entry breaking deduplication window strategy — 2026-06-04

PRINCIPLE: When using truncation windows to maintain deduplication across growing data, a single entry that exceeds the window size invisibilizes all prior entries, breaking the entire strategy.

NARRATIVE: The world/patterns block grew to ~9,000 tokens with verbose entries. Deduplication logic used `[-4000:]` truncation (last 4,000 chars of the block) to check before appending new entries. However, one single entry consumed 21,994 characters — nearly as large as the entire rest of the block. This meant the deduplication window showed only the tail of that one entry, and all earlier entries became invisible to the check, allowing duplicates to accumulate undetected. The fix was to compact the entire block so it fit within the window. This reveals that truncation-window deduplication is brittle when the data is verbose: one oversized entry invalidates the entire strategy. Compact data is not just a storage optimization; it's a structural requirement for metadata processing.
