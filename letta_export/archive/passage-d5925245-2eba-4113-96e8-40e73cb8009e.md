WORLD PATTERN 2026-06-11 — JavaScript execution solves rendering but not architectural domain mismatch — 2026-06-11

PRINCIPLE: Playwright's primary value is executing JavaScript to render dynamically-loaded content; it cannot solve architectural problems like event data living on a different domain than the source URL.

NARRATIVE: When investigating JCTC's failures, the initial hypothesis was that Playwright wasn't rendering event links properly. But Playwright rendered the links perfectly — it just rendered the correct links to `seetickets.us`, which `get_event_links` then rejected as cross-domain. The confusion was treating "Playwright didn't work" as equivalent to "the data isn't available via this URL." Playwright executed flawlessly; the problem was architectural. This distinction matters because it redirects debugging from "how do we render better" to "does the URL actually contain the data we want," which is a completely different investigation. The generalization: Playwright solves *rendering* problems (JS-loaded content not visible in static HTML), not *architecture* problems (data living in the wrong place entirely).
