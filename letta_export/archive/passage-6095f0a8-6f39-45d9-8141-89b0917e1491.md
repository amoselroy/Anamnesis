SUMMARY
During the live run to catch up on pending events, row 625 (Jersey City Summit for Real Estate) failed to post with the error "Could not find Post button." The event had an image attachment, and investigation revealed a systematic issue: after uploading an image in the Facebook composer modal, the contenteditable field selection logic broke. The code used `.last` to find the text input, which after image upload would grab the image caption field instead of the main post text area. Additionally, after typing text and uploading an image, clicking the Post button would time out at 30+ seconds with silent interception.

Systematic debugging through screenshots revealed the root issues: (1) the text was being cleared when the image was uploaded, (2) multiple contenteditable fields existed after image upload and the selector was ambiguous, and (3) the Post button existed and was visible but the Playwright `click()` method was being intercepted by Facebook's modal overlay layer, causing repeated 30-second timeout retries.

The fix involved three changes: (1) type post text before uploading the image (when only one contenteditable field exists), (2) scope contenteditable searches to the correct context, and (3) replace Playwright's `click()` method with JavaScript direct click (`page.evaluate("el.click()")`) to bypass the interception layer entirely. The JS click executes in milliseconds instead of timing out, allowing the Post button to fire cleanly. This fix unblocked not just row 625 but all previously stalled image-attached event and exhibition posts that were silently failing with the same issue.
