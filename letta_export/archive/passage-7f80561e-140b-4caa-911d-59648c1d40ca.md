SUMMARY
During platform review, clicking the condition tag on the Lecanemab therapy page triggered a "Therapy Not Found" error that broke the page entirely. Initial investigation suspected a code bug in how the frontend extracts the slug or processes condition data. Systematic debugging revealed the error manifested differently depending on Render cold-start state: when the service was cold and still spinning up, the API request timed out, producing the "Therapy Not Found" message; when the service was warm, clicking the condition worked perfectly and displayed impressive condition-specific scoring with written rationale. Root cause identified: this was not a code bug but a cold-start timing issue. The frontend's catch block was doing double duty — catching both genuine HTTP failures (404 errors) and transient/timeout failures — and displaying the same unhelpful "Therapy Not Found" message for both scenarios, making them indistinguishable to users. Amos noted this had happened before due to log file access failures (NameError: name 'log' is not defined in the therapies router, fixed in commit d63c19c on June 18), but the current manifestation was different: a cold-start timeout showing the same symptom. Decision made to fix the frontend rather than immediately upgrading the Render plan, as the retry/warm-up messaging fix would provide better user experience and diagnostic clarity.
