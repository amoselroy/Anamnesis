WORLD PATTERN 2026-06-10 — Graceful fallback from missing database table — 2026-06-10

PRINCIPLE: When a feature depends on a newly-added database table, the code should gracefully fall back to working without it rather than crash, so missing schema doesn't break the entire feature.

NARRATIVE: The condition alias resolution feature (`_resolve_condition_slug`) tried to query the newly-created `condition_aliases` table, but a stale environment variable caused local runs to target the wrong database where the table didn't exist yet. This threw an `UndefinedTable` error that propagated to the user as "Therapy not found." The fix was to wrap the alias lookup in a try-except that falls back to direct slug matching if the table doesn't exist. This allowed the feature to degrade gracefully: users could still access therapies by canonical slug while the missing table was being created in production. The pattern generalizes: any schema extension should include fallback logic so the feature operates at reduced capability rather than failing completely if the table is missing.
