WORLD PATTERN 2026-06-19 — PostgreSQL shared-transaction silent abort cascading to dependent statements — 2026-06-19

PRINCIPLE: When running multiple DDL statements in a single PostgreSQL transaction, any failure marks the entire transaction aborted; all subsequent statements silently skip without error, leaving schema diverged from expectations.

NARRATIVE: During Braindexer migration deployment, `_run_migrations()` ran all ALTER TABLE statements in a single transaction. When a unique index creation failed (due to pre-existing duplicates or the index already existing), PostgreSQL marked the transaction as aborted. All subsequent ALTER TABLE statements silently did nothing, meaning the new `shown_condition_ids` and `excluded_condition_ids` columns were never created. The application continued to run (no startup error), but any code attempting to read or write these columns threw 500 errors. This is harder to diagnose than a loud failure because the system appears functional. The fix: wrap each migration statement in its own savepoint, so a failure in one doesn't cascade to the rest. This pattern applies anywhere you're running multiple DDL operations in sequence — either use savepoints or run each in a separate transaction entirely.
