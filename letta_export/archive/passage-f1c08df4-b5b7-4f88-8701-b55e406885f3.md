WORLD PATTERN 2026-06-18 — Startup-time schema guarantee via FastAPI lifespan — 2026-06-18

PRINCIPLE: Running database schema migrations in the FastAPI application startup lifespan, before accepting requests, guarantees schema never diverges from code and surfaces migration failures loudly at startup rather than silently in production.

NARRATIVE: After deploying a new `side_effects_score` column, the production database was missing it despite `preDeployCommand: python setup_db.py` being configured in render.yaml. The SELECT query now included the column, causing condition queries to fail with 500 errors that the JS caught as "Therapy not found." To make schema changes bulletproof, a `_run_migrations()` function was added to the FastAPI lifespan that runs all critical `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` statements before the server begins accepting requests. Each migration is individually try-excepted, so a single failure (e.g., column already exists) doesn't block startup, but migrations that actually fail are visible in logs. Going forward, adding a column requires only adding it to the `_MIGRATIONS` list—no dependency on preDeployCommand succeeding or external deployment steps. This pattern ensures application code and database schema never diverge, which is particularly important in cloud-deployed systems where migration scripts may fail silently.
