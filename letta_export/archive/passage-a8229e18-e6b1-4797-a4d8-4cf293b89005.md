SUMMARY
Major architectural overhaul of the MemShepherd chunk archival pipeline. The original design called Letta inline at SessionEnd, but Letta narrative generation (~120s at 157K tokens) exceeded the hook timeout — entries were never written. Redesigned to a deferred-queue architecture: the hook writes a lightweight .pending.json job descriptor (containing jsonl_path + byte offsets, not a copy of the conversation text) and exits in under one second. The worker, running async at next SessionStart, re-reads the JSONL from the stored offsets, extracts conversation text, and makes the Letta call without timeout pressure.

Semantic chunking replaced fixed-count splitting. The hook writes one pending job per block. The worker asks Letta to identify genuine topic shifts (not mechanical turn counts) using a structured prompt with '=== TOPIC BOUNDARY ===' delimiters and TOPIC: labels. Letta returns one or more sections; the worker inserts one archival passage per section into pgvector on Neon.

A two-phase commit pattern was added to handle partial failures: after Letta returns sections (phase 1), they are cached into the .pending.json file with passage_id=null. Each successful insert_archival() call updates that section's passage_id and writes back to the file immediately. On retry, phase 1 is skipped entirely and only null-passage_id sections are re-attempted — preventing duplicate Letta calls and duplicate DB entries.

The pending JSON stores jsonl_path + start_offset + end_offset rather than a conv_text copy, making the JSONL the single source of truth. The worker re-derives conversation text, structured metadata, and preview at job time.

archival_search.py was also fixed: both subprocess.run calls now use encoding='utf-8', errors='replace' to handle non-ASCII psql output (Windows cp1252 default was crashing).

MIN_USER_TURNS reduced from 3 to 2: Matrix-injected session context arrives as system-reminder, not counted as human dialog turns, so sessions with 2 substantive turns were being dropped.
