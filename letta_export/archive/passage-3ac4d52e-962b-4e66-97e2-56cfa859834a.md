WORLD PATTERN 2026-06-06 — Backup strategy selection based on content sensitivity — 2026-06-06

PRINCIPLE: Choose backup infrastructure based on the sensitivity and local specificity of the content, not just convenience or industry standard.

NARRATIVE: After achieving a stable, working Facebook poster, the question arose how to preserve the version. Git was initialized locally, but the question of a GitHub remote followed naturally. However, the project contains local paths (Windows-specific directory structures like `C:\Users\Amos\...`), session files, and configuration sensitive to the local environment. Rather than defaulting to "put it on GitHub," the decision was made to keep git local-only (still providing version control and rollback capability) and implement offsite backup via Google Drive instead (copying files to `My Google Docs\DEV\fb-poster\`). This avoided exposing local paths and environment-specific configuration in a public or even private repo, and was consistent with the pattern of other local-only projects. The principle generalizes: backup strategy should account for what's being backed up — infrastructure with heavy local dependencies and session files may be better served by cloud storage mirrors than by source control platforms that expect portable, environment-agnostic code.
