Facebook Poster Text Input After Image Upload - Full Debugging Cycle

Session 2026-06-06 debugging the core Facebook poster failure: posts with Image Type = "none" trigger Pexels fallback image upload, but text input to the post composer was failing after image attachment.

PROBLEM STATEMENT
User provided DevTools HTML inspection confirming the target element exists: `div[data-lexical-editor="true"][aria-placeholder="Write something..."]` with `contenteditable="true"` and `role="textbox"`. The issue was not element detection but text input itself — text was not landing in the composer after image upload.

APPROACHES ATTEMPTED & OUTCOMES
1. **JS focus() + page.keyboard.type()** - Failed. Screenshots showed "Write something..." placeholder still visible after typed content was logged. Root cause: Playwright's keyboard input requires internal pointer-focus state, which JS-only focus does not establish.

2. **.click() followed by keyboard.type()** - Timed out. Grammarly's shadow DOM overlay was blocking Playwright's pointer-based clicks in early attempts. This is why JS focus() was tried.

3. **.click(force=True)** - Also failed to land text visibly, though logged as successful. The `.first` selector was hitting a hidden/stale element rather than the visible text area.

4. **Finding by geometric visibility** - Attempted `page.locator('...').filter(has_role('textbox')).first` with visibility checks. Partial progress but still not reliable.

5. **document.execCommand('insertText')** - SUCCESS. This approach inserts text directly into the focused contenteditable element at the DOM level, bypassing Playwright's keyboard API entirely. Works like browser extensions and password managers inject text. Confirmed working in 7 AM scheduled run.

CRITICAL DISCOVERIES
- The memory file from previous session stated "URL must be stripped from text when image is uploaded" because "typing URL causes FB to switch to link-post mode." This was incorrect interpretation. Manual testing showed URL in post after image works fine in browser. The actual problem was text not entering at all.
- The post-image 8-second wait (`page.wait_for_timeout(8_000)`) would sometimes cause browser freeze/hang if the Pexels upload made the tab unresponsive. Switching to Python's `time.sleep(8)` unblocked this — Python's sleep doesn't depend on browser event loop.
- The original Post button search was scoping to `role="dialog"` which picks up the notifications panel instead of the composer, leaving the Post button search with no buttons. This was a separate issue from text input.

WORKING SOLUTION (Confirmed)
Text input path after image upload now uses:
1. `page.evaluate()` with JS click + focus on the Lexical editor element
2. `page.evaluate()` with `document.execCommand('insertText', false, text)` to inject text directly into contenteditable
3. Python `time.sleep(8)` instead of browser-dependent wait for image processing

This sequence is confirmed working end-to-end in the 7 AM 2026-06-06 scheduled run: Pexels image fetched → uploaded → text injected → post submitted → post visible on Facebook group.

REMAINING ISSUES IDENTIFIED
Two events (7th Inning Stretch, Food & Wine Walk) continue failing on Post button detection with error "Could not find Post button" despite visual presence. These are link-preview posts (typed URL triggers Facebook's link-preview overlay). The Post button search needs adjustment for link-preview dialog state.
