SUMMARY
Discussion of whether to add automatic clearing of stuck retry flags when agencies come back online. The retry cap (3 attempts) was designed to prevent admin-panel spam when an agency is persistently down (e.g., ANVISA's IP block), but the cap is too aggressive — it locks the system even after a transient outage recovers without manual intervention. The minimal fix: when the daily checker detects `attempt > MAX_ATTEMPTS`, probe the agency's endpoint with a cheap HEAD request before giving up. If reachable, reset to attempt 1 and run a full sync; if still unreachable, stay silently flagged (don't burn an agency sync). Tal implemented this logic: attempts 1–3 retry daily with notifications; on cap hit, probe the endpoint; if back up, auto-reset and sync; if still down, stay silently flagged. This handles transient outages like FDA's while preserving the quiet-flag behavior for genuinely persistent blocks like ANVISA (which remains excluded from `_PROBE_URLS` and the automated pipeline).
