WORLD PATTERN 2026-06-23 — Google Drive API scoping: My Drive vs Shared Drives — 2026-06-23

PRINCIPLE: Cloud storage APIs often have implicit scope limitations that create false discovery failures when assumptions about visibility are wrong.

NARRATIVE: When building the Braindexer grant tracker, the system attempted to search Google Drive for an existing "Grant Applications" folder that Amos had created locally on G:\. The API search returned no results, suggesting the folder didn't exist. This led to creation of duplicate nested folders (Grant Applications → Braindexer → Braindexer), which appeared to be a mistake. The root cause: Google Drive's API searches only My Drive by default, not Shared Drives. If Amos's folder structure was in a Shared Drive or on a local mirror that hadn't fully synced, the API search would legitimately return nothing even though the structure existed. This pattern generalizes: cloud storage systems, databases, and search APIs often have implicit scope boundaries (specific account, specific organization, specific visibility tier) that make "not found" results ambiguous — they mean either "doesn't exist" or "not visible in current scope." Diagnostic strategy should always validate scope assumptions before concluding absence.
