This triggered a full design session for an automatic archival pipeline. Key design decisions confirmed with Amos:

ARCHITECTURE: chunk_archive.py replaces session_end.py in PreCompact and SessionEnd hooks entirely. Sends ONE combined message to Letta per boundary: the chunk transcript (from last byte-offset to EOF) with a narrative request appended. The regular Letta agent responds with the narrative (inserted to archival_passages). The sleep-time companion agent processes the same exchange for core block consolidation. One Letta call, one transcript delivery, both purposes served — no Letta internal code changes required.

CHUNKING: Context_watch.py boundary events are the natural chunking signal (PreCompact fires at strong boundaries). Byte-offset state tracked in TEMP/memshepherd_arc_{session_id}.json prevents double-archiving when both PreCompact and SessionEnd fire in the same session.

HYBRID ENTRIES: Deterministic structured metadata (files touched from Edit/Write tool inputs deduplicated, error types deduplicated to unique 80-char signatures, tool names, URLs, dates) + LLM narrative (Letta agent, no length cap). Names, locations, explicit decisions, and unusual terms handed to LLM narrative — not extractable deterministically without NLP.

SUBSTANCE THRESHOLD: Minimum 3 user turns AND 1500 chars extracted text. Below threshold: skip insertion entirely (no Letta signal for trivial sessions).

IMPLEMENTATION: chunk_archive.py written (~420 lines), committed to MemShepherd repo (commit 89ca2b7), pushed to GitHub. claude_settings.json updated: session_end.py removed from PreCompact and SessionEnd hooks, chunk_archive.py added to both. session_sync.py unchanged (Git backup of Letta state at SessionEnd).
