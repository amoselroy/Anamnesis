SUMMARY
Amos reported that the FB Poster is selecting absurdly unrelated images for event posts — drag shows paired with church picnic photos, haunted tours with smiling-families stock photos — a mismatch so severe it reads like parody. Tal investigated the image pipeline and identified three paths: "source" type (relies on FB's OG scrape), "native"/"generic" type (uses scraped image URL), and "none" type (falls back to Pexels). The problem was in path 3: the `_infer_event_type` function was mapping event titles to only 8 hard-coded categories, and anything that didn't match (drag shows, wine tastings, haunted tours, comedy nights, murder mysteries) all fell into "community gathering event," which then queried Pexels for "community gathering event" → smiling people at a picnic. The fix was straightforward: when no category matches, use the actual event title words as the Pexels query instead of the inferred type. This preserves the 8 existing hardcoded categories (yoga, concert, art, etc.) but allows specialty/nightlife events to get semantic results based on their actual titles. The change was implemented and deployed live. Secondary question resolved: "source" posts do not get generic images attached; they show whatever OG image FB scrapes from the event page itself, which is outside the scraper's control at post time.
