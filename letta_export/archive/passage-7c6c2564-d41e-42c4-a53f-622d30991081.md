SUMMARY
A critical design conversation emerged about ensuring primary venue sources get credit when events appear in both primary and aggregator feeds. The initial rotation-order approach (running aggregators last) proved fragile — aggregators could still run first in a given cycle and "own" the event. A new architecture was designed and fully implemented: (1) Add `Type` column to source sheets (`Primary` or `Aggregator` — later standardized to `"primary"` / `"secondary"`); (2) Add `Source Type` column to pending/posted event sheets, populated on every new scrape; (3) Redesign deduplication to match events by `(date, time, venue)` across the worksheet instead of pre-loading a set; (4) When a primary source finds a match to a secondary-sourced row already in the sheet, overwrite that row in place rather than skip it as a dupe. The design included three options for implementation: live patching during scrape (Option A, chosen) vs. post-run reconciliation. The venue matching strategy was simplified to normalize both to lowercase and use the shorter string as a substring check to handle venue name variations (e.g., "Art House Productions" vs. "Art House Productions, Jersey City, NJ"). All implementation choices were confirmed: normalize venues with substring matching, treat blank Source Type as primary (legacy safety), and proceed with Option A (live overwrite during scrape). A subtle regression was discovered and fixed: removing the `date_venue_title_time` set broke within-run deduplication (same event from multiple URLs in a single source). The fix introduced a lightweight `dtv_seen` set that tracks events added during the current run, catching duplicate URLs for the same event before they hit the worksheet. Full implementation included: migration script to add columns to both sheets, modifications to `load_pending_dedup()`, rewrite of `_build_row()` with worksheet scan + overwrite logic, updates to `scrape_source()`, `get_targets()`, and `main()`, updates to all test scripts. Smoke tests confirmed the new system works correctly and within-run duplication is properly caught.
