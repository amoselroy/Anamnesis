WORLD PATTERN 2026-07-02 — Parameterized behavior prevents caller-sensitive branching drift — 2026-07-04

PRINCIPLE: When the same function is called from different contexts with legitimately different needs, explicit parameters make behavioral differences clear and auditable, whereas caller-detection logic inevitably diverges.

NARRATIVE: When restructuring MemShepherd's hook pipeline, `chunk_archive.py --process-queue` needed to behave differently when called synchronously from `SessionStart` (bounded by a 180s timeout, must emit additionalContext) versus asynchronously from `SessionEnd` (unbounded, no context injection). The first instinct was to have the function sense its caller via environment variables or context, adjusting behavior accordingly. This pattern ("detect who called me") is seductive because it keeps the function's interface stable, but it immediately creates a maintenance trap: as behavior diverges (one caller needs different retry logic, another different timeouts), the implicit branching scatters throughout the function body. The better approach was explicit parameters (`--budget-seconds`, `--no-context`), making behavioral differences declarative at the call site rather than hidden in the function. Over time, as new callers are added or callers' needs change, explicit parameters keep those differences auditable at the point where they matter (the hook configuration), rather than buried in function logic that gets re-examined only when something breaks.
