SUMMARY
Mirroring the existing `therapy_aliases` pattern, a `condition_aliases` table was added to support multiple names for the same condition (e.g., "ALZ" and "Alzheimer's Disease" both resolve to the same record). This serves two critical purposes: preventing the AI from creating duplicate conditions when condition detection returns different name variants, and enabling users to search and filter by any known alias. The conditions router was extended with full CRUD endpoints for alias management (`POST /conditions/{slug}/aliases`, `DELETE /conditions/{slug}/aliases/{alias_id}`), allowing curators to add or remove aliases through the admin panel. The `_upsert_detected_conditions` function in the scraper was updated to check both condition names and aliases before creating new records, resolving detected condition names through the alias table to match existing records when available. Both condition filtering in `list_therapies` and condition slug resolution in `get_therapy` were updated to use a new `_resolve_condition_slug` helper that checks the alias table, ensuring users can filter and access condition-specific pages regardless of which alias name they use.
