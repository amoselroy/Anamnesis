SUMMARY
Amos observed that the displayed scientific papers mixed directly relevant efficacy studies with tangential papers (mechanism studies, biomarker expression, tangential mentions) and requested a way to determine and sort by relevance level. A three-tiered relevance scoring system was implemented: `relevance_score SMALLINT` (1/2/3) added to the sources table representing direct efficacy/safety study, indirect research (mechanism, biomarker, animal model), and tangential mention respectively. Three-tiered was chosen over percentage scoring because LLMs make reliable categorical judgments (direct vs. indirect vs. tangential) but struggle with false precision in numeric scales; 73 vs 75 has no meaningful difference. In the research pipeline, a new Haiku call `_score_source_relevance` was added to batch-score all newly-researched papers in a single prompt, extending the same API call that `assess_therapy_signals` already makes — the additional cost was minimal. Papers are now sorted by relevance tier (direct papers first), then by date within each tier. Display shows a colored dot indicator: green for direct, yellow for indirect, gray for tangential. A backfill endpoint was created to score existing sources that predated the feature, with a "Backfill Relevance" button in the admin header that polls for completion and shows live progress ("Scoring… 47 left"). After recognizing that backfill was only needed once because future Research runs will auto-score new sources, and that the button would rarely be needed going forward, the global backfill button was removed and replaced with a per-therapy "Rank Papers" button (a fast, synchronous operation scoring just one therapy's papers via a single Haiku call that completes under 30 seconds).
