**TOPIC: Letta Authentication Gap — Discovery, Root Cause Analysis, and Fix Implementation**

Session opened with memory loading failure: MemShepherd's orientation/pins fetch returned HTTP 401 during session initialization. Investigation revealed the root cause: on 2026-07-15, the Letta container was hardened with password authentication (rebound to 127.0.0.1:8283, configured with SECURE=true and LETTA_SERVER_PASSWORD, using Letta's built-in middleware). The hooks layer received the corresponding update to `letta_ops.py` to send Bearer token Authorization headers, but this was incomplete — the hardening pattern was not propagated everywhere it was needed.

Systematic audit revealed widespread scope: `session_start.py`'s `fetch_blocks()` and `fetch_persona_block()` functions build raw `urllib.request.Request` objects without any Authorization header, causing the immediate memory load failure. But the problem extended far beyond this single file. `chunk_archive.py` itself (responsible for archival writes) contained 8 unauthenticated request sites across its insert/fetch/patch functions. Additionally, approximately 11 standalone scripts (`world_trim.py`, `update_world.py`, `update_persona.py`, `pins_append.py`, `intuitions_append.py`, `archival_insert.py`, `reconcile_pins.py`, `seed_archive.py`, `create_blocks.py`, `dump_world_block.py`, `export_world_block.py`) all built raw HTTP calls to Letta without authentication.

Active incident identified: at 02:41 UTC on 2026-07-16 (tonight), a real archival insert batch hit 401 four times and became stuck in `.pending.json` — not lost (thanks to prior partial-failure gating) but stuck and accumulating, failing on every retry attempt.

Rather than attempt mass-edits across 14 files without verification, Amos dispatched the repair to Fable (another agent in the deployment) with full incident context, constrained to edit-only operations (no writes against the live Letta server or the stuck pending file). Fable chose a consolidation approach, adding a shared seam to `letta_ops.py` — new public functions `auth_headers(headers=None)` and `build_request(path, data, method, headers)` — which captures the 2026-07-15 incident as the reason this seam is mandatory. All 13 request sites in the pipeline were routed through this single seam, leaving each script's retry/timeout/urlopen semantics unchanged; only auth, base URL (now honoring MEMSHEPHERD_LETTA_URL everywhere), and Content-Type defaults were centralized.

Fable completed with read-only verification: `py_compile` passed on all 14 edited files; a negative-control test confirmed the server genuinely enforces auth (deliberate unauthenticated GET returned 401); and positive tests exercised every read-only code path through each patched module's functions. `session_start.py` was run end-to-end with real persona content loaded successfully. Write paths were verified by code inspection (identical construction to the passing read-only paths). Notably, `archival_search.py` required no fixes — it only talks to Voyage AI and psql, never the Letta HTTP API.
