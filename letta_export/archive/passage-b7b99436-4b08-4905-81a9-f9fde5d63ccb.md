SUMMARY
After rate limiting was resolved, research on Gamma Sensory Stimulation continued to fail silently with a 10-minute timeout, yet logs showed no errors. By adding detailed progress logging to `research_therapy()` (emitting log.warning() for each major phase), Amos was able to pinpoint the exact failure: `'NoneType' object has no attribute 'strip'` in the research endpoint handler. The root cause was in `_build_context()`: when fetching mechanism from the therapy dict, `therapy.get('mechanism', '')` returns `None` if the key exists in the DB but the value is NULL (the default only applies if the key is missing entirely). Calling `.strip()` on `None` crashes the thread. Gamma Sensory Stimulation had `mechanism = NULL` in the database. The fix was defensive: `therapy.get('mechanism') or ''` ensures the fall-through value is always a string. After deploying this fix, research on Gamma Sensory Stimulation completed successfully, pulling 33 papers (compared to zero before). This incident reinforced the pattern: when a background thread fails silently (because exceptions aren't surfaced to the browser), explicit progress logging at each phase is essential for diagnosis. The NULL mechanism value should have been caught during DB schema design; this revealed a gap in defensive coding for optional fields that exist in the schema but are legitimately NULL.
