WORLD PATTERN 2026-06-18 — Code variable ordering dependencies surfaced only after deploy — 2026-06-18

PRINCIPLE: Variable definitions that are used later in the same function can cause NameErrors that don't surface in local testing if the code path isn't exercised in the same order, particularly when local and production environments have different data structures.

NARRATIVE: The news scraping loop was inserted before the `linked_conditions` variable was defined, causing a NameError on production but not during local testing (because the local dev database was structured differently and the code path may have been partially exercised or bypassed). The error only surfaced after deploying to Render and testing with production data. The fix required careful code placement: the news loop had to run after line 577 where `linked_conditions` is populated from the database. The lesson generalizes: code placement matters for variable scope and definition order, and these issues may not surface in local testing if the data differs between environments. Static analysis tools can catch some of these, but the safest approach is explicit awareness of definition order in longer functions and testing the exact same code path against both local and production-like data structures before deploy.
