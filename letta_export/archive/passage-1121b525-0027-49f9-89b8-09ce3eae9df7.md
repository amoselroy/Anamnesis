SUMMARY
Amos noted that a recently-added pharmaceutical compound, MK-2214 (code-named, no brand name), wasn't appearing on the main therapies listing despite having been researched and sources successfully scraped. Investigation revealed two separate mechanisms at play: `create_therapy` (the form for adding a new therapy) never writes to `therapy_conditions` at all — the schema's `TherapyCreate` model lacks a condition field — and linking a therapy to a condition is handled as a separate manual step in the admin UI. This alone would be a gap but not a crisis. The deeper structural issue was that `_detect_related_conditions()`, the automatic condition-detection function run during every `research_therapy()` call, was taking a `sources` parameter but never using it. The function's prompt asked Claude "based on your knowledge of this specific therapy" with zero reference to the actual papers, trials, and other sources that had just been scraped and stored. For well-known compounds with training-data footprint, this approximation works because background knowledge matches reality. For code-named early-stage compounds like MK-2214 with no branded identity or significant publication history, the model correctly returned "I don't know of any conditions this treats" — a silent, well-formed, incorrect answer — even though a real, on-topic PubMed paper on tau-immunotherapeutics was sitting in the database waiting to be used. The fix involved grounding the LLM detection in the actual scraped sources: filtering to scientific source types, injecting titles and notes snippets directly into the prompt, and rewriting the instruction to ask Claude to "ground your answer primarily in what the sources above actually study" with background knowledge as a supplement. End-to-end testing against MK-2214's real source confirmed the fix now correctly infers Alzheimer's Disease plus multiple tauopathy-related conditions (PSP, CBD, FTD, CTE, Parkinson's) from the paper's actual content. The downstream mechanics worked correctly: `_upsert_detected_conditions` already had proper slug generation and alias matching to route the detected names into the correct existing condition rows. The immediate fix manually linked MK-2214 to Alzheimer's Disease, restoring it to the main list. The structural fix was committed and pushed as a one-line change to the prompt and source-handling logic.
