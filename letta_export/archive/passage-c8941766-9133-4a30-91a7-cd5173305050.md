SUMMARY
Amos requested a two-step Manage News interface: step 1 selects a condition from the therapy's active conditions, step 2 displays article management options scoped to that condition. Implementation was straightforward and was completed across `static/admin.html` with state variables (`_newsModalSlug`, `_newsModalConditionSlug`, `_newsModalConditionName`) and functions (`openNewsModal`, `_showConditionSelector`, `selectNewsCondition`, `_loadNewsModalContent`). The modal includes a breadcrumb showing the selected condition and passes the condition slug as a query parameter to all API calls. A subtle UX refinement was applied: when a therapy has only one active condition, the selector step is auto-skipped and the user goes directly to the articles list, reducing unnecessary clicks. Testing revealed that the feature worked conceptually but uncovered a deeper architectural issue: the database schema for condition-scoped visibility had not yet been properly implemented, causing articles not to appear as expected.
