SUMMARY
Dr. Sano had explicitly asked for the default sort to be based on strength of evidence rather than alphabetical order. Amos noted this had to be fixed before her next site visit. Additionally, Daimon discovered that effectiveness, evidence, and overall scores weren't displaying in the main listing view — they showed as NULL because the homepage list query read from `therapies` table directly, but scores are stored in `therapy_conditions`. The root cause: the default (no-condition-filter) query on the homepage had no context about which condition's scores to show, so it returned NULLs. Daimon implemented a multi-part fix: (1) rewrote the query using a LATERAL JOIN to pull scores from `therapy_conditions` for the selected condition context (defaulting to Alzheimer's Disease), (2) changed the default sort from `ORDER BY name` to `ORDER BY evidence_score DESC`, (3) updated the frontend default sort state indicator to show the correct column. The deploy included all three fixes. Verification showed correct sorting: Lecanemab (4/5 evidence) at top, cluster of 3s, cluster of 2s, descending. Two issues emerged on verification: Donepezil (re-added live during the demo) showed 0 evidence score because it had no summaries/scores generated yet, and its name appeared lowercase ("donepezil") instead of title case. These were addressed immediately in a follow-up fix. The sorting implementation also revealed a deeper design question: since scores are condition-specific, the listing view now requires a condition context to be meaningful. This led to the decision to make Alzheimer's Disease the default condition, prominently displayed, to prevent confusion about which context's scores are being shown.
