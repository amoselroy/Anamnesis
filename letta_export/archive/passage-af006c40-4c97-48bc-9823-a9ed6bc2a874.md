WORLD PATTERN 2026-06-29 — Bulk regulatory data import creating storage sustainability questions on shared hosting — 2026-07-01

PRINCIPLE: Bulk import of regulatory databases (hundreds of thousands of records) to enable re-matching across new therapies creates a storage sustainability problem on free or shared hosting tiers, forcing a tradeoff between write-once deduplication and per-request API queries for active conditions only.

NARRATIVE: The agency migration plan proposed bulk CSV downloads (FDA ~30MB, ANVISA ~100MB) stored persistently in agency_approvals table to support re-matching when new therapies are added. Without this staging, unmatched records are discarded and can't be re-matched. However, Amos correctly identified that storing hundreds of thousands of regulatory records might consume Braindexer's free Neon database allocation. The architectural tradeoff: bulk storage provides write-once matching and deduplication via UNIQUE(agency, record_key), but accumulates storage indefinitely; per-therapy API queries eliminate intermediate tables but require N API calls per sync cycle and don't support historical re-matching. Filtering by active conditions only would reduce volume but doesn't solve the fundamental storage/execution cost tradeoff. This pattern recurs whenever importing reference data from large external sources (regulatory databases, taxonomy systems, news archives) — the decision to persist bulk imports vs. query on-demand has long-term cost implications that scale with dataset size and usage pattern.
