WORLD PATTERN 2026-08-12 — Dormant source persistence in indefinite monitoring — 2026-08-12

PRINCIPLE: Monitoring systems that replay historical logs have no concept of source retirement; dormant sources remain flagged until explicitly removed or cross-checked against active configuration.

NARRATIVE: Jersey City Theater Center had already been retired (removed from the live event source sheet) prior to this session, but monitor.py replays all historical log entries indefinitely. The retired source never logged an attempt after 2026-07-28, yet remained in the failure report because monitoring was based purely on log history without checking whether the source was still active. The fix was adding an active-source lookup cross-checking flagged names against the live configuration before reporting them as failures. This applies to any long-running monitoring system maintaining historical logs: without explicit retirement/deactivation handling, dormant entities accumulate in reports indefinitely. The distinction between "never worked" and "used to work, now retired" must be tracked separately from monitoring statistics.
