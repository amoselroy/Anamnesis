WORLD PATTERN 2026-06-18 — Heuristic guards that silently filter valid data — 2026-06-18

PRINCIPLE: Heuristic filters designed to catch invalid inputs can inadvertently reject valid data when the heuristic doesn't account for legitimate variation in the data domain.

NARRATIVE: During AlzForum scraper development, an integer-mechanism guard was added to reject rows where mechanism was a bare number (suspected UI artifacts). The guard caught "View Timeline" (a button with mechanism "18"), but Amos correctly identified the flaw: legitimate pharmaceutical mechanisms can be numeric (e.g., "16S rRNA"), and the guard would silently drop them from the database. The heuristic was solving a real problem (UI noise) but at the cost of data loss that would only become apparent when a legitimate numeric mechanism arrived. The better approach was targeted filtering on UI keywords ("View Timeline", "Edit", etc.) rather than broad type-based filtering. The pattern generalizes: when a heuristic guard filters by type/format rather than semantic content, it risks silently dropping valid data. The danger is the silence — the data never appears, no error is raised, and the loss may not be noticed for sessions or weeks.
