WORLD PATTERN 2026-06-24 — Transient pool connection errors on fresh deploy masquerading as code bugs — 2026-06-24

PRINCIPLE: When a service receives a fresh deployment and immediately experiences a 500 error that succeeds on retry, the root cause is typically transient infrastructure (connection pool re-establishment) not code logic.

NARRATIVE: The first HTTP POST to add a therapy returned a 500 error; the second attempt seconds later succeeded without any code change. Initial diagnosis suspected a code bug in the create_therapy endpoint. Root cause was that Render completed the fresh deployment, causing the connection pool to re-initialize. The first request hit the service while it was still establishing database connections — a transient problem, not a persistent code issue. This pattern distinguishes infrastructure-transient errors from code bugs: if the same operation succeeds immediately on retry without code changes, suspect connection pooling, cache invalidation, or service startup race conditions rather than code logic.
