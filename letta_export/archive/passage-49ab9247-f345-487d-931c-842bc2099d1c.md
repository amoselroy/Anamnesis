SUMMARY
After implementing soft-delete (articles marked `deleted_at` instead of hard-deleted), the recovery interface was missing — users had no way to discover or restore removed articles. The implementation had a fundamental flaw: `_loadNewsModalContent()` used `Promise.all`, which meant if the deleted-news fetch failed for any reason, the entire modal body would error and the active article list would disappear, creating the illusion that nothing was removed rather than surfacing an error. The fix was to decouple the deleted-news call from the Promise.all chain so that a failure on that call wouldn't break the active list. A fallback message was added: if the deleted-news call fails, it displays "Could not load removed articles: <error>" so the failure is visible. For the Removed section itself, a persistent empty state was added that appears when nothing has been removed yet: "No removed articles. Use Remove on any article to soft-delete it — it can be restored here." Once articles are removed, they appear in that section with individual Restore buttons. The cleanup decoupling revealed that soft-deletes were actually working (the deleted_at column was being written), but the modal was just failing to show them. After deploy, the Removed section became visible and fully functional.
