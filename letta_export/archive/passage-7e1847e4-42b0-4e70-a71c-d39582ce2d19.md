WORLD PATTERN 2026-08-06 — Companion URL Enrichment Architecture for Merged Event Details — 2026-08-06

PRINCIPLE: When event details are scattered across multiple pages (listing on one page, supplementary details on another), a generic `companion_url` field on SiteHandler enables fetching and merging both sources without source-specific logic.

NARRATIVE: LSC After Dark lists events on the main series page, but speaker names and talk titles live only on a separate Space Talk page. Rather than hardcode LSC-specific logic to fetch both pages, Tal designed a generic `companion_url` concept: the SiteHandler declares an optional companion page; the scraper fetches both primary and companion, runs LLM extraction on both, maps companion content by date, and appends matching companion data to event descriptions before writing rows. The pattern is reusable — if another venue has similar architecture, the same mechanism applies — while remaining generically implemented rather than LSC-specific. This is more maintainable than either creating custom handlers or duplicating events with partial data from each page.
