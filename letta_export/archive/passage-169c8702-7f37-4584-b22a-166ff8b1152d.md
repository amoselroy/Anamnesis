WORLD PATTERN 2026-06-22 — Three-table staging-diff-stable architecture for periodic data reconciliation — 2026-06-23

PRINCIPLE: When reconciling periodic external data imports, staging table + stable table + in-application diff is cleaner and more maintainable than storing snapshot history across all imported rows.

NARRATIVE: Initial regulatory monitoring implementation stored 60K raw rows in `agency_snapshots` table, diffing across all rows each run. User recognized this was suboptimal and proposed instead: `agency_import` (staging table, discarded and replaced each run), `therapy_regulatory_status` (stable, one row per target entity with consolidated cross-agency fields), and diff logic in code that loads both and compares. This eliminated historical row accumulation, simplified matching and suggestion generation, and kept Neon storage lean. The pattern generalizes to any periodic external data import where the goal is detecting changes: stage the new data, load the previous target state, compute deltas in application code, update target table. Cleaner than maintaining a growing append-only history of snapshots and more explicit about what's actually being tracked.
