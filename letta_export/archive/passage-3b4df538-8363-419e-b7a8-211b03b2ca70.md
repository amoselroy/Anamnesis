SUMMARY
Amos reported that selecting Alzheimer's Disease from the condition list on a therapy detail page returned "Therapy not found." Investigation revealed a compound failure: (1) a JavaScript scope error in the `therapy.html` template where the `renderDashboard` function referenced `condData` directly, but `condData` was a local variable inside `render()`, not accessible to the function taking `scores` as a parameter; and (2) a missing database column that was the root cause of the 500 error that triggered the frontend error handling. The `pathway_tags` column had been added to `setup_db.py` schema definition but never migrated to the live Neon database, so the `condition_data` query in `get_therapy` was selecting a non-existent column and throwing an `UndefinedColumn` error. When the backend returned 500, the frontend's try/catch caught it and displayed the generic "Therapy not found" message. Both fixes were applied: the DB migration was run to add `pathway_tags` to the `therapy_conditions` table, and the frontend variable reference was corrected from `condData` to `scores`. This revealed how alias expansion (the `_resolve_condition_slug` function) depends on downstream query correctness — a missing column in one branch breaks the entire feature.
