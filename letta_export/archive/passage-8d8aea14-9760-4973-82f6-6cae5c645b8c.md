WORLD PATTERN 2026-06-04 — Local spreadsheet as single source of truth for configuration and runtime state — 2026-06-03

As system complexity grows, runtime state (rotation tracking, last-scrape timestamps, error counts) can drift into hidden storage (SQLite databases, environment variables, external APIs). This visibility gap creates maintenance problems: operators cannot see what the system is doing, changes are invisible until behavior changes unexpectedly, and system state becomes fragmented across multiple stores. The refactoring principle: consolidate configuration and runtime state into the same user-visible location (the local .xlsx) by adding columns like `Last Scraped` (for rotation logic) and `Last Count` (for monitoring). This makes system behavior transparent, eliminates hidden dependencies, and allows operators to edit state directly (correcting a stuck rotation by manually adjusting a date). The principle generalizes: for systems Amos builds, prefer the local data file (xlsx) as the single source of truth, with code reading/writing to it directly, over external databases or config files that hide state from the user's view.
