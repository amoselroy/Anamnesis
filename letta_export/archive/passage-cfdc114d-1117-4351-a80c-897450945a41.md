SUMMARY
The user proposed building a curated, accessible resource to track emerging Alzheimer's therapies — both for personal management and to fill a gap in physician/patient resources between dense academic literature and advocacy-driven information. This sparked the design of Braindexer, envisioned as a multi-phase platform with Phase 1 focusing on a curated therapy database with automated research monitoring, Phase 2 adding member submission forms to flag undocumented therapies, and Phase 3 adding user accounts and discussion forums. The core differentiator would be three-level summarization of each therapy entry: clinical rigor for physicians, informed-individual level for engaged patients like Amos, and layperson-friendly explanations for general readers. Discussion of naming produced a strong list (Cognitude, Cogniscience, Neurascent, Braindex, Braindexer), with braindexer.org emerging as likely available and the strongest candidate. The database schema was designed with full semantic search from the start (pgvector + Voyage AI, using existing Neon infrastructure from MemShepherd), including tables for therapies, sources (papers, articles, media with typed source fields), and therapy_relationships (a directed graph with typed edges allowing semantic mapping of relationships between approaches). Critically, Amos emphasized the need for extractability — the schema was deliberately isolated in its own `braindexer` schema with its own `BRAINDEXER_DB_URI` environment variable, allowing clean separation from MemShepherd and future migration to an independent Neon instance. The project structure was initialized with git, folder hierarchy, and pseudocode for the full Phase 1 build (FastAPI app, database access layer, scraping automation, summarization pipeline, frontend templates, deployment plan).
