WORLD PATTERN 2026-06-11 — Local development database isolation from production by configuration — 2026-06-11

PRINCIPLE: Local development environments may connect to a completely separate database instance than production (not just a different schema in the same instance), and this separation is often invisible until a write is attempted against expected production data.

NARRATIVE: The Braindexer project has two distinct Neon database branches: one pointed to by `.env` (development) and one used by the Render deployment (production). Local diagnostic queries against the `.env` DB appear to work correctly (no errors), but return empty result sets because the development DB has zero data. This invisibility was discovered when trying to verify that the ICTRP scraper had written data — the local query said "no data exists," but the data was actually in production. The issue generalizes: local `.env` files often point to isolated dev/test databases, and there's no built-in warning when queries succeed against the "wrong" database. The fix is to route production data updates through the deployed API endpoints rather than attempting local database operations.
