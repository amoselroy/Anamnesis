SUMMARY
Amos initiated a multi-part improvement to Braindexer's therapy summaries: (1) verify the overall assessment score formula (suspecting a `+2` overcorrection), (2) add three mandatory structured sections—Effectiveness, Safety, and Side Effects—to all audience-level summaries, (3) enable dashboard cards to link directly to these sections via anchor jumps, and (4) understand the distinction between the Research & Summarize and Summarize-only pipelines. Initial investigation confirmed the overall score formula was already correct—`(effectiveness + safety + (6 - side_effects)) / 3` naturally produces the 1–5 range without needing any offset. The misleading comment claiming a "shift" was needed was removed. Implementation involved three parallel changes: (1) Added a module-level `_SECTION_INSTRUCTION` constant in `summarizer.py` that explicitly requires three H2 headers (Effectiveness, Safety, Side Effects) and substantive narrative synthesis under each. All three audience prompts (Plain English, Informed, Clinical) were updated to append this instruction, replacing the old layperson-specific "End with one concrete sentence" guidance. The `_summarize()` function's `max_tokens` default was bumped from hardcoded 1024 to 1800 to accommodate the longer structured output. (2) JavaScript helpers were added to `therapy.html`: `assignSectionIds()` uses tolerant `startsWith` matching to assign stable anchor IDs (`eff-section`, `safety-section`, `side-effects-section`) to rendered H2 headers, post-render via `querySelectorAll`, making it resilient to LLM output variations. A `sectionLink()` helper generates clickable anchor symbols (↓) with hover effects. The `applyTab()` function calls `assignSectionIds()` immediately after rendering the summary box. (3) Dashboard cards in condition mode were updated to include section links: the Effectiveness, Safety, and Side Effects Severity card labels now include `sectionLink()` calls, allowing users to jump from summary metrics directly to supporting narrative in the summaries below. The `generate_general()` function (cross-condition blurb shown when no condition is selected) was deliberately left untouched since section cards don't appear in that mode. Research & Summarize differs from Summarize-only by including the full scraping pipeline (PubMed, ICTRP, AlzForum, custom sources, deduplication) before summarization, whereas Summarize-only re-runs the LLM on existing database sources. API cost estimation revealed the structured output roughly 2.3× the previous output token count (from ~400 to ~900 tokens per call across three calls), pushing per-condition Summarize cost from ~$0.02 to ~$0.05. A full therapy with 3 conditions costs approximately $0.15–0.17 per run. Existing therapy entries require re-running Summarize to pick up the new structured sections and rendered anchor links.
