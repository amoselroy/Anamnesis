SUMMARY
User observed that the current implementation shows only "Alzheimer's Disease" chip despite having multiple conditions in the database, which prompted realization that the architecture has a fundamental flaw: summaries and assessment scores (therapeutic_action, effectiveness_score, evidence_score, evidence_level) are condition-dependent, not therapy-invariant. The same therapy's effectiveness against Alzheimer's vs. Lewy Body Dementia would require different summaries and scores. The current design has these fields on the `therapies` table, treating them as therapy-level properties when they actually need to be per-condition properties. This discovery revealed that moving to a many-to-many relationship between therapies and conditions requires simultaneously restructuring the data model — the junction table needs to hold not just the link but also the condition-specific metadata. The insight is architectural: therapies are not standalone entities but rather node pairs in a bipartite graph where therapy-condition pairings are the actual data-bearing units.
